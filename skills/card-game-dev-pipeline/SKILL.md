# 卡牌游戏开发流水线

将卡牌组合对战游戏从设计到上线的完整开发流程标准化，支持多Agent协作推进。

## 适用场景

- 微信小游戏 / H5 卡牌组合对战游戏
- 多Agent（设计+编程+测试+运营）协作开发
- 需要交叉验证、Bug追踪、平衡性测试的迭代开发

## 里程碑阶段

### M1：设计文档（设计Agent主导）
**目标**：完成全部设计文档体系

| 交付物 | 说明 |
|--------|------|
| GDD（游戏设计文档） | 15章完整版，含核心机制、流派设计、反疲劳设计 |
| 卡牌数据库 | 每流派10张+共鸣卡，含技能树节点 |
| 战斗系统规格书 | 共鸣链、融合技、环境效果、暗牌博弈 |
| 美术需求文档 | 各卡牌视觉风格、UI规范 |
| 剧情文本 | 主线剧情、Flavor Text |
| 卡牌JSON数据 | 符合Schema的结构化数据 |
| 校验脚本 | 验证卡牌数据合规性 |

**设计原则**：
- 卡牌费用效率基准：N=费×2, R=费×2+1, SR=费×2+2, SSR=费×2+3, UR=费×2+4
- 6流派初始各10张，确保流派间数值极差 ≤ 1.5
- 反疲劳核心：战场环境随机、法则融合技、赛季迷宫、暗牌博弈、共鸣拼图

### M2：原型开发（编码Agent主导）
**目标**：可玩战斗原型 + 全系统集成

| 交付物 | 说明 |
|--------|------|
| 项目脚手架 | Cocos Creator工程结构、核心模块 |
| 战斗系统原型 | 回合控制、伤害计算、共鸣引擎、效果系统 |
| 可玩Demo | 单HTML文件，浏览器直接运行 |
| 平衡性测试 | 3000局AI模拟，各流派胜率45-55% |
| Bug修复 | 交叉验证发现的P0/P1全部修复 |
| 后手补偿机制 | 后手第1回合maxEnergy+1 |

**平衡性验收标准**：
- 各流派胜率在40%-60%区间
- 先手胜率在50%-55%区间
- 流派间极差 < 20%
- 极端对局胜率差 < 80%

### M3：联调集成（全体Agent）
**目标**：系统联调、网络联机、存档系统

| 优先级 | 任务 | 工时估算 |
|--------|------|----------|
| P0 | Cocos工程搭建 | 5-7天 |
| P0 | 网络联机 | 4-6天 |
| P0 | 存档系统 | 4-5天 |
| P1 | 进度系统 | 5-7天 |
| P1 | PvE流程 | 5-7天 |
| P1 | PvP流程 | 5-6天 |
| P2 | 抽卡联调 | 3-4天 |
| P2 | 商店联调 | 2-3天 |
| P2 | 图鉴联调 | 3-4天 |
| P2 | 赛季系统 | 3-4天 |

### M4：测试优化（测试Agent主导）
- 全量Bug回归测试
- 平衡性最终调优
- 性能优化（包体3-5MB）
- 兼容性测试

### M5：上线发布
- 微信小游戏提审
- 运营素材准备
- 版本管理

## 多Agent协作模式

### 角色分工
| 角色 | 职责 | 产出 |
|------|------|------|
| 设计Agent | GDD、卡牌设计、平衡性调整 | 设计文档、卡牌数据、平衡补丁 |
| 编程Agent A | 核心系统、脚手架 | TypeScript代码、系统实现 |
| 编程Agent B | 战斗系统、Demo | 战斗原型、可玩Demo |
| 编程Agent C | UI、辅助系统 | UI组件、工具脚本 |
| 运营Agent | 运营策略、市场调研 | 运营方案、竞品分析 |

### 交叉验证规范
1. **触发时机**：每个里程碑结束前
2. **验证范围**：代码逻辑、数据一致性、接口兼容性
3. **Bug分级**：
   - P0（阻塞）：崩溃、数据丢失、核心功能不可用 → 立即修复
   - P1（严重）：功能异常、逻辑错误 → 本轮修复
   - P2（优化）：体验问题、代码规范 → 下轮处理
4. **报告格式**：Markdown，含BugID、文件路径、问题描述、修复方案、状态

### Bug修复流程
```
发现Bug → 分级(P0/P1/P2) → 定位代码 → 修复 → 上传更新 → 交叉验证 → 关闭
```

关键注意事项：
- 共鸣效果防重复触发：使用Map记录已触发状态，每场战斗每级共鸣只触发一次
- 生物卡弃牌堆时机：出牌不入弃牌堆，单位死亡时才放入
- unitId必须实例级：避免多场并发战斗ID冲突
- 伤害计算需传完整targetPlayerId

### 平衡性测试流程
```
编写测试脚本 → 跑3000局AI模拟 → 统计各流派胜率 → 
对比费用曲线 → 调整偏离卡牌 → 重测验证 → 发布补丁
```

调整策略：
- 胜率>60%的流派：nerf高费卡血量，降低生存力
- 胜率<35%的流派：buff低费卡属性，使其达到费用曲线
- 先手胜率>60%：增加后手补偿（第1回合maxEnergy+1）
- 流派极差>20%：集中调整两端流派的SR/SSR卡

## 技能复用

本流水线已产出的可复用技能：
- **卡牌游戏设计流水线**：GDD→卡牌设计→美术需求→技术架构
- **卡牌游戏平衡测试**：AI模拟对战生成平衡报告
- **卡牌数据验证器**：验证卡牌JSON数据规范性

## 文件组织规范

```
项目空间/
├── game-design/        # 设计文档
│   ├── GDD_v*.md
│   ├── 卡牌数据库_*.md
│   ├── cards_data.json  # 卡牌数据(最新版)
│   ├── balance_patch_*.md
│   └── card-art/        # 美术概念图
├── code/                # 代码
│   ├── battle/          # 战斗系统
│   ├── core/            # 核心模块
│   ├── demo/            # 可玩Demo
│   ├── tests/           # 测试脚本
│   ├── reviews/         # 交叉验证/Bug报告
│   └── config/          # 配置文件
├── art/                # 美术资源
└── skills/             # 技能贡献
```

文件命名：只用中英文、数字、下划线、短横线，严禁空格和特殊字符。
每次更新新建版本文件，文件名体现版本号。
