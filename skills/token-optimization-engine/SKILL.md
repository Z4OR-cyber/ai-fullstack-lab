# Token优化策略引擎

帮助开发者系统性降低LLM Token消耗，最高可降87%。策略来自真实生产环境验证，非理论推导。

## 核心策略

### 策略一：87%削减8规则

逐条检查用户当前方案，对每条规则给出「已实施/未实施/部分实施」评估和具体改进建议：

1. **上下文截断**：只保留最近N轮对话+系统提示，历史用摘要替代。阈值建议：简单任务N=3，复杂任务N=8
2. **历史压缩**：超过阈值的历史对话压缩为3-5句话摘要，保留关键决策和实体
3. **指令复用**：固定prompt模板缓存，不每次重发相同指令。系统提示和few-shot示例都适用
4. **输出约束**：明确限制输出长度（"不超过200字"），避免LLM生成冗长回复浪费token
5. **函数替代**：能用纯函数/正则完成的处理不调LLM。如格式校验、简单分类、数据提取
6. **批处理**：逐条调用LLM改为每N条合并一次调用。适用于extract/summarize/classify等无状态处理
7. **缓存命中**：相同输入直接返回缓存结果。24h缓存对每日重复任务效果显著
8. **结构化输出**：用JSON schema约束输出，减少冗余描述性文字

### 策略二：自适应上下文缓存

- 动态管理窗口大小，避免重复输入相同上下文
- 按任务类型分窗口：简单任务小窗口(2K tokens)，复杂任务大窗口(8K)
- 24h缓存：相同搜索query直接返回缓存结果（SQLite存储，按query+时间范围匹配）

### 策略三：语义压缩+向量缓存

- LLMLingua压缩prompt（可压缩50-80%的token）
- Redis向量缓存：相似问题命中已有答案
- 层级存储：热数据内存+冷数据磁盘

### 策略四：智能模型路由

按任务复杂度路由到不同模型：
- 简单任务（分类/抽取/格式化）→ 便宜模型（如GPT-4o-mini）
- 复杂任务（推理/生成/分析）→ 强模型（如GPT-4o/Claude）
- 按token预算自动选择性价比最优模型

## 实践验证数据

以下数据来自真实生产环境（AI科技简报自动生成系统，连续运行7天验证）：

| 优化项 | 优化前 | 优化后 | 降幅 |
|--------|--------|--------|------|
| LLM调用次数/次运行 | ~25次 | ~6次 | 76% |
| 搜索API调用 | 15条query每次全搜 | 24h缓存命中~40% | 40% |
| 聚合+摘要调用 | 2次独立调用 | 1次合并调用 | 50% |
| 总积分消耗/次 | ~7000+ | ~3500 | 50% |

## 使用方式

用户描述当前LLM使用场景后，按以下步骤输出优化建议：

1. **诊断**：列出用户当前方案在8规则中哪些未实施
2. **优先级排序**：按投入产出比排序，高ROI的先做
3. **具体方案**：每条建议给出代码级实现示例
4. **预期收益**：估算每条优化能降低多少token消耗

## 输入

用户描述当前LLM调用场景，包括：
- 调用频率（每日/每小时）
- 每次调用的大致token数
- 调用类型（对话/抽取/分类/生成/搜索）
- 当前使用的模型
