# 卡牌游戏设计流水线

将一个游戏创意转化为完整的、可开发的设计文档体系。核心价值：标准化流程 + 可并行 + 可迭代 + 可复用。

## 适用场景

- 设计卡牌对战游戏（CCG/TCG/DBG混合型）
- 已有游戏概念，需要产出完整GDD和设计文档
- 需要批量设计卡牌数据（含技能树、平衡分析）
- 需要规划赛季运营、氪金系统、美术需求

## 流水线总览

```
Stage 1: 概念定义 → GDD框架（世界观/流派/核心机制）
Stage 2: 卡牌设计 → 各流派卡牌数据库（含技能树）
Stage 3: 系统规格 → 战斗系统规格书 + 环境卡库
Stage 4: 内容填充 → 迷宫事件库 + 剧情文本
Stage 5: 交付准备 → 美术需求文档 + 任务看板
```

## Stage 1: GDD框架

### 输入
- 游戏类型（卡牌对战/牌组构筑/混合）
- 平台（微信小游戏/H5/手游）
- 核心卖点（1-3个差异化特色）
- 参考游戏

### 产出文档：GDD v1
包含14个章节：
1. 游戏概述（基本信息、三大卖点、核心循环）
2. 世界观与主线（法则/流派体系、章节结构）
3. 剧情引导（轻交互设计、解锁条件）
4. 卡牌系统（卡牌结构、类型、稀有度、扩展架构）
5. 流派卡池（流派定位、核心机制、跨流派组合）
6. 共鸣组合机制（共鸣链规则、共鸣发现）
7. 技能成长系统（卡牌等级、分支技能树、流派精通）
8. 牌组构筑（规则、策略、推荐模板）
9. 战斗系统（基本设定、回合流程、特殊机制、胜负判定）
10. 持续运营（赛季系统、段位、日常活跃、活动轮换）
11. 氪金点设计（变现架构、货币体系、抽卡系统、保底机制）
12. 社交系统（好友、公会、分享裂变）
13. 开发路线图（MVP→Alpha→Beta→上线）
14. 技术架构建议（前端/后端/平台接入）

### 关键设计决策
- **流派数量**：首发6个流派，每赛季可新增
- **每流派卡数**：首发20张/流派，基础包120张
- **共鸣机制**：同法则2/3/4/5张触发递进共鸣，跨法则有专属融合效果
- **技能树**：5个节点(Lv3/6/9/12/15)×二选一分支，Lv15觉醒获新立绘
- **反疲劳设计**：战场环境随机、法则融合技、Roguelike PvE、暗牌博弈、每日解谜、动态共鸣条件

## Stage 2: 卡牌设计

### 设计原则
1. **数据驱动**：每张卡由标准化模板定义，新增卡只需填数据+美术+测试
2. **费用效率基准**：N=费用×2, R=费用×2+1, SR=费用×2+2, SSR=费用×2+3, UR=费用×2+4（攻+命总和）
3. **稀有度分布**：每流派 N×2 | R×3 | SR×3 | SSR×1 | UR×1
4. **费用曲线**：1/2/2/3/3/4/4/5/6/7（每流派10张）
5. **技能树三路线**：纯输出/节奏/混合，确保同卡不同养法

### 卡牌数据结构
```
卡牌ID | 名称 | 法则 | 稀有度 | 费用 | 类型(战灵/法术/领域/共鸣)
攻击力 | 生命值 | 技能描述 | 标签 | 背景故事
技能树: 5节点×2分支 (SR+卡牌)
觉醒形态: 名称 + 新能力 + 新立绘
```

### 并行设计策略
- 每个流派可独立设计，适合并行
- 每2个流派为一组派发子agent（共享平衡框架）
- 跨流派共鸣卡在所有流派完成后统一设计
- 每组完成后产出：卡牌数据库 + combo示例 + 平衡分析

### 平衡验证
- 费用效率验证（每张卡的攻+命+技能价值 vs 费用）
- 流派对决分析（优势/劣势/关键点）
- combo总伤害估算（理想情况 vs 实际情况）
- UR卡专项分析（是否过强/过弱/依赖铺垫）

## Stage 3: 系统规格

### 战斗系统规格书
- 回合结构：6个阶段（回合开始→出牌→结束前→结束→战斗→移交）
- 效果系统：8种效果类型 + 数据结构定义
- 状态效果详细规则：燃烧/冻结/感电/护盾/嘲讽/速攻/穿透
- 共鸣系统：判定流程 + 触发时序 + 融合规则
- 伤害结算：计算流程 + 多攻击者 + 伤害类型分类
- 环境系统：触发时序 + 排位/休闲差异化
- 暗牌系统：暗置流程 + 预测机制
- 边界case：手牌溢出/满员/超时/多次共鸣/死亡时序/复活/抽空
- 游戏状态机：状态定义 + 转换图 + 断线重连
- 数值公式：伤害/抽卡概率/匹配

### 环境卡库
- 首发30种环境效果，分7类（能量/共鸣/战斗/生命/视觉/法则/特殊）
- 每种环境含：效果描述 + 策略影响 + 强度(weak/normal/extreme) + 模式限制
- 环境组合规则：冲突检测 + 排位赛环境池(10种weak)
- 流派交互分析表：环境 × 流派优势矩阵
- 赛季扩展规划：每赛季+5种

## Stage 4: 内容填充

### 迷宫事件库
- 30+种事件（好运/坏运/赌博/选择/战斗/商人/谜题）
- 20种遗物（通用5 + 每流派2-3专属）
- 5个Boss（独特机制 + 应对策略 + 奖励）
- 路线结构设计（层数/节点分布/难度曲线）

### 剧情文本
- 6章主线，每章800-1200字
- 对话气泡格式：NPC发言 + 2选项 + 跳过
- 每章：剧情节点 + 战斗前对话 + 章节结尾 + 解锁卡牌背景
- 选择分支纯表现，不影响数值

## Stage 5: 交付准备

### 美术需求文档
- 整体风格定位 + 色彩规范(6法则色板)
- 卡牌美术规范：尺寸/布局/卡框(5种稀有度)/卡面要求/觉醒形态
- UI界面规范：主界面/战斗/抽卡/牌组构筑
- 特效规范：法则粒子 + 战斗特效 + 性能要求
- 资源清单：MVP/Alpha分阶段，含数量/格式/命名规范
- AI生图指引 + 外包建议 + 预算估算

### 任务看板
- 按角色分组：游戏设计/开发/运营/美术
- 任务依赖关系图
- 协作规则：文件目录/数据格式/同步方式

## 并行执行策略

### 可并行的任务
- Stage 2的各流派卡牌设计（每2流派一组）
- Stage 3的战斗规格书和环境卡库
- Stage 4的迷宫事件库和剧情文本
- Stage 5的美术文档和任务看板

### 并行分配原则
- 每个子agent需要完整的上下文（GDD框架+平衡基准+数据结构）
- 不同流派的子agent共享同一套费用效率和稀有度分布规则
- 跨流派内容（共鸣卡/跨流派combo）在所有流派完成后统一设计
- 所有产出统一命名规范和目录结构

## 迭代扩展支持

### 新增流派流程
```
设计法则概念 → 定义关键词机制 → 设计20张初始卡 → 测试跨流派combo → 上线
```
每个新流派作为「新发现的法则」引入世界观，自然融入剧情。

### 赛季内容更新
- 新卡包30-50张（新法则或旧法则扩展）
- 新赛季法则（全局规则修改器）
- 新主线章节
- 新环境效果(+5种)
- 新迷宫Boss

### 平衡调整
- 卡牌数据修改不影响已有技能树路线
- 环境效果调整不影响基础规则
- 新流派上线前需测试与所有已有流派的交互

## 注意事项

1. 每个文档头部标注版本号、日期和对应GDD版本，方便追踪
2. 卡牌ID全局唯一，按流派分段编号（001-020流派A, 021-040流派B...）
3. 所有combo示例需要标注总费用和总伤害，方便平衡验证
4. 美术需求文档中的AI生图prompt需要具体到角色描述+法则元素+风格参考
5. 任务看板需要标注任务依赖关系，避免开发阻塞
6. 数值平衡是持续过程，首版以"可接受"为目标，通过模拟对战微调
