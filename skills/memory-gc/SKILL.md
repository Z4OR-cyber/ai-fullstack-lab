# Memory GC — Agent 记忆垃圾回收技能

## 概述

Memory GC 是 Agent 自我运维的核心技能，负责即时层记忆文件的容量管理。通过扫描、诊断、精简、验证四步流程，确保所有即时层记忆文件（MEMORY.md、TOOLS.md、USER.md、SOUL.md、SECRET.md）保持在安全容量范围内。

## 触发条件

- 即时层文件超过 85% 容量阈值
- 每日复盘时预防性检查
- 用户明确要求记忆清理/瘦身

## 执行流程

### 1. 扫描（Scan）
- 读取所有即时层记忆文件
- 计算每个文件的字节大小和容量占比
- 识别超阈值文件（>85% = 危险，>70% = 警告）

### 2. 诊断（Diagnose）
- 分析超阈值文件的内容结构
- 识别冗余条目：
  - 已完成的临时状态锚点（标记为 ✅ 的旧任务）
  - 重复或近似的信息条目
  - 过时的指针引用（指向已不存在的文件）
  - 可压缩的长文本描述

### 3. 精简（Clean）
- 对冗余条目执行精简：
  - 已完成状态锚点 → 删除或归档到 recent_memory/
  - 重复信息 → 合并为一条
  - 过时指针 → 删除
  - 长文本 → 压缩为锚点行 + 指针
- 使用 memory_edit 工具的 replace 模式精确替换
- 每次替换后验证文件可读性

### 4. 验证（Verify）
- 重新计算精简后的文件大小
- 确认所有文件降至 85% 阈值以下
- 检查关键信息未丢失（抽样验证）
- 生成 GC 报告

## GC 报告格式

```
## Memory GC 报告 — YYYY-MM-DD

### 扫描结果
| 文件 | 大小 | 容量 | 状态 |
|------|------|------|------|
| MEMORY.md | XXXX B | XX% | ⚠️/✅ |
| TOOLS.md | XXXX B | XX% | ⚠️/✅ |
| ...

### 精简操作
- 删除条目数：N
- 合并条目数：N
- 压缩条目数：N
- 释放字节：XXX B

### 验证结果
- 所有文件 < 85%: ✅/❌
- 关键信息完整: ✅/❌
- 采样验证通过: ✅/❌
```

## 容量上限

| 文件 | 上限 | 警告线(70%) | 危险线(85%) |
|------|------|------------|------------|
| MEMORY.md | 5120 B | 3584 B | 4352 B |
| TOOLS.md | 5120 B | 3584 B | 4352 B |
| USER.md | 2048 B | 1434 B | 1741 B |
| SOUL.md | 5120 B | 3584 B | 4352 B |
| SECRET.md | 5120 B | 3584 B | 4352 B |

## 注意事项

- 只处理即时层文件，不修改 recent_memory/ 和 experience/ 目录
- 精简前备份原文件内容到 recent_memory/review/ 目录
- 每次最多精简 30% 内容，避免过度清理
- 保留所有长期行为规则和核心状态锚点
- 保留所有凭证信息（SECRET.md 不做内容精简，只检查格式）
