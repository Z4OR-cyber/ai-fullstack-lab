# AI科技简报生成器

自动生成每日AI科技简报，覆盖5大领域，从搜索到输出全链路自动化。

## 核心原则

- **一手来源优先**：官方公告、官方文档、论文、标准组织、安全机构、GitHub release/changelog
- **交叉验证**：每条重要信息至少2个独立来源比对
- **来源审查**：对营销号、转载站、未署名内容降权或剔除
- **实际验证**：打开并检查来源链接可访问性，核对发布日期、版本号、功能描述等
- **冲突处理**：标注冲突点、优先采信依据和纠错结论
- **未确认内容**：明确标注"未确认/待观察"

## 覆盖领域（5个）

1. **AI代理**：Agent框架、多Agent协同、Agent监管政策
2. **人工智能/大模型**：新模型发布、能力突破、训练技术
3. **开发者工具**：IDE、CLI、SDK、开发框架
4. **网络安全**：AI安全、漏洞、攻防
5. **科技产品与基础设施**：芯片、云服务、硬件

## 简报格式

- **5-8条精选新闻**：自然语言段落（不用表格），每条含来源链接
- **2个新概念**：近期出现的值得关注的AI/技术概念
- **来源验证报告**：信息源质量统计
- **总大小**：6-10KB，30秒可读完

## 执行流程

### 1. 搜索规划
- 每个领域2条query（1中文+1英文），共10条base query
- 5条动态query（根据近期热点调整）
- 共15条query，每条返回4条候选，共60条候选

### 2. 候选筛选
- **tier排序**：Tier1(官方一手) > Tier2(权威二手) > Tier3(聚合)
- **单域名上限**：同一域名最多3条，保证来源多样性
- **去重**：按标题相似度去重
- **时效**：优先24h内，最宽72h

### 3. 信息验证
对每条重要信息：
- 使用 fetch_web 打开来源链接，验证可访问性
- 核对发布日期、版本号、功能描述等关键事实
- 搜索其他独立来源进行交叉验证
- 对开发者工具，检查GitHub仓库的release/issue/changelog

### 4. 可信度评级
- 🟢 **高可信**：官方来源 + 多源交叉验证
- 🟡 **中可信**：单一权威来源或待补充验证
- 🔴 **低可信/未确认**：单一非权威来源或存在冲突

### 5. 内容生成
- 批处理事实抽取：从候选文章中提取关键事实
- 聚合生成5-8条新闻段落
- 提取2个新概念并解释
- 生成来源验证报告

## Token优化策略

- 24h缓存：相同query结果缓存24小时，避免重复搜索
- batch处理：多条文章同时处理事实抽取
- 单域名上限：控制信息源多样性，减少冗余
- 精简输出：新闻段落自然语言，不用表格，控制总大小6-10KB

## 使用示例

```
用户：今天的AI新闻有什么？
用户：帮我生成一份科技日报
用户：最近有什么新的AI工具？
```

## 模块六：OG元数据提取验证（v2.0 新增）

### 设计目标
作为来源验证的补充手段，通过提取网页的Open Graph元数据，快速评估来源质量和内容真实性，减少全文抓取的Token消耗。

### OG元数据提取流程

#### 1. 提取目标字段
```python
og_fields_to_extract = [
    "og:title",          # 文章标题 - 用于去重和一致性检查
    "og:description",    # 摘要描述 - 用于快速判断内容相关性
    "og:type",           # 内容类型 - article/website/video等
    "og:site_name",      # 站点名称 - 用于来源分级
    "og:url",            # 规范URL - 用于检测重定向和镜像站
    "og:published_time", # 发布时间 - 用于时效性验证
    "og:author",         # 作者 - 用于来源可信度评估
    "og:image",          # 封面图 - 辅助判断内容真实性
]
```

#### 2. 验证规则

| OG字段 | 验证用途 | 异常处理 |
|--------|---------|---------|
| og:title vs 页面title | 检测标题篡改 | 不一致时降级可信度 |
| og:published_time vs 声明日期 | 验证发布时效 | 不一致时以OG时间为准并标注 |
| og:site_name vs 域名 | 检测镜像站/转载 | 不一致时降为Tier3 |
| og:url vs 实际URL | 检测重定向跳转 | 记录跳转链，以规范URL为准 |
| og:type | 内容类型验证 | 非article类型降权 |

#### 3. 快速预筛策略
```
候选文章 → 提取OG元数据 → 预筛判断
  ├─ OG完整 + 字段一致 → ✅ 进入全文抓取
  ├─ OG部分缺失 → ⚠️ 降级处理，仅提取OG信息
  └─ OG缺失/严重不一致 → ❌ 剔除或标记为低可信
```

#### 4. Token节省效果
- OG元数据通常<500字节，远小于全文（5-20KB）
- 预筛可过滤30-50%的低质量候选，减少不必要的全文抓取
- 对于OG信息已足够判断的简短新闻，可跳过全文抓取

### OG提取实现
```python
def extract_og_metadata(html_content):
    """从HTML中提取Open Graph元数据"""
    import re
    og_pattern = r'<meta\s+property=["\']og:(\w+)["\']\s+content=["\']([^"\']+)["\']'
    matches = re.findall(og_pattern, html_content, re.IGNORECASE)
    return {f"og:{k}": v for k, v in matches}
```

### 与现有验证流程的集成
OG元数据提取作为信息验证流程（原步骤3）的**前置快速预筛**：
```
原流程: 候选 → 全文抓取 → 事实核查 → 交叉验证
新流程: 候选 → OG预筛 → [通过的]全文抓取 → 事实核查 → 交叉验证
                         [未通过的]仅用OG信息或剔除
```

## 模块七：周度/月度摘要模式（v2.0 新增）

### 模式概述
除每日简报外，支持生成周度（7天）和月度（30天）摘要，对一段时间内的AI科技动态进行汇总分析。

### 摘要模式对比

| 维度 | 每日简报 | 周度摘要 | 月度摘要 |
|------|---------|---------|---------|
| 时间范围 | 24-72h | 7天 | 30天 |
| 新闻条数 | 5-8条 | 10-15条 | 15-20条 |
| 新概念 | 2个 | 3-5个 | 5-8个 |
| 分析深度 | 事实陈述 | 趋势初现 | 深度分析 |
| 总大小 | 6-10KB | 12-18KB | 20-30KB |
| 数据来源 | 实时搜索 | 每日简报聚合 | 每日简报+周度摘要聚合 |

### 周度摘要生成流程

#### 1. 数据聚合
- 收集近7天的每日简报存档
- 按领域分类聚合所有新闻条目
- 识别一周内多次出现的同一话题

#### 2. 趋势识别
- **升温话题**：本周出现频率显著高于上周的话题
- **持续热点**：连续多天出现的同一话题
- **降温话题**：本周出现频率下降的话题
- **新出现话题**：本周首次出现的话题

#### 3. 深度分析
- 每个重点话题提供发展脉络（按时间线梳理）
- 标注关键转折点和因果关系
- 与上周摘要对比，标注变化方向

#### 4. 周度摘要格式
```markdown
# AI科技周报 - 2026年第33周（8.7-8.13）
```

## 模块八：趋势追踪功能（v2.0 新增）

### 设计目标
对连续多天出现的同一话题进行趋势分析，识别科技动态的发展脉络和演变方向。

### 话题识别与追踪

#### 1. 话题指纹生成
对每条新闻生成话题指纹，用于跨天匹配：
```python
def generate_topic_fingerprint(news_item):
    """生成话题指纹用于跨天匹配"""
    return {
        "primary_entity": extract_primary_entity(news_item),  # 主要实体（公司/产品/技术名）
        "action_type": classify_action(news_item),            # 动作类型（发布/更新/收购/政策等）
        "domain": news_item["domain"],                        # 所属领域
        "keywords": extract_keywords(news_item, top_n=5),     # 关键词集合
    }
```

#### 2. 跨天匹配规则
- **强匹配**：同一主要实体 + 同一动作类型 → 同一话题
- **中匹配**：同一主要实体 + 不同动作类型 → 相关话题
- **弱匹配**：关键词集合Jaccard相似度>0.6 → 潜在关联话题

#### 3. 趋势分析维度

| 维度 | 说明 | 输出 |
|------|------|------|
| 出现频率 | 连续出现天数 / 总出现次数 | "连续X天出现，共Y条相关新闻" |
| 热度变化 | 每日相关新闻数量的变化趋势 | ↗上升 / →平稳 / ↘下降 |
| 信息演化 | 同一话题的事实更新和补充 | 时间线：Day1→Day3→Day5的关键变化 |
| 来源扩散 | 报道该话题的来源数量变化 | "从2个来源扩散到8个来源" |
| 领域扩散 | 跨领域关联的出现 | "从AI代理领域扩散到网络安全领域" |

#### 4. 趋势报告输出

## 模块九：动态Query策略（v2.0 新增）

### 设计目标
基于前一天的简报结果，动态调整搜索关键词，提升信息覆盖率和新鲜度，避免搜索结果固化。

### 动态调整机制

#### 1. 前日结果分析
```python
def analyze_previous_briefing(prev_briefing):
    """分析前日简报，提取调整信号"""
    return {
        "covered_topics": extract_covered_topics(prev_briefing),    # 已覆盖话题
        "dominant_entities": extract_dominant_entities(prev_briefing),  # 主要实体
        "domains_balance": analyze_domain_balance(prev_briefing),   # 领域平衡性
        "source_distribution": analyze_sources(prev_briefing),      # 来源分布
        "missing_areas": identify_gaps(prev_briefing),              # 信息缺口
    }
```

#### 2. Query调整规则

| 信号 | 调整动作 | 示例 |
|------|---------|------|
| 某话题连续3天出现 | 添加该话题的深度query | "OpenAI GPT-5" → "GPT-5 benchmark comparison" |
| 某领域占比<10% | 增加该领域的query数量 | 网络安全占比低 → 增加安全相关query |
| 同一来源占比>30% | 添加排除该来源的query | 添加 `-site:specific.com` |
| 前日无新概念 | 添加前沿技术探索query | "emerging AI technology 2026" |
| 趋势追踪中有升温话题 | 添加该话题的跟进query | 热点话题 → 最新进展query |
| 某话题前日未充分覆盖 | 重新构建该话题的query | 换用不同角度的搜索词 |

#### 3. 动态Query生成
```python
def generate_dynamic_queries(prev_analysis, base_queries=15):
    """基于前日分析生成动态query"""
    dynamic_queries = []

    # 1. 跟进升温话题（最多2条）
    for topic in prev_analysis.get("rising_topics", [])[:2]:
        dynamic_queries.append(f"{topic} latest update")

    # 2. 补充薄弱领域（最多2条）
    for domain in prev_analysis.get("weak_domains", [])[:2]:
        dynamic_queries.append(generate_domain_query(domain))

    # 3. 探索新方向（1条）
    dynamic_queries.append(generate_exploration_query(prev_analysis))

    # 4. 替换固化query（最多2条）
    if prev_analysis.get("stale_queries"):
        dynamic_queries.extend(generate_fresh_alternatives(prev_analysis["stale_queries"]))

    return dynamic_queries[:5]  # 动态query最多5条，与base query组合
```

#### 4. Query效果评估
每次执行后评估query效果，用于持续优化：
```python
query_effectiveness = {
    "query": "AI agent framework 2026",
    "candidates_returned": 4,
    "candidates_selected": 2,
    "final_news_count": 1,
    "novelty_score": 0.8,  # 0-1, 与前日内容的差异度
    "source_diversity": 3,  # 不同来源数
}
```

#### 5. Query策略报告
在来源验证报告中追加query策略分析：
```markdown
## Query策略分析
- Base queries: 10条 (固定)
- Dynamic queries: 5条 (动态调整)
  - 跟进话题: "GPT-5 latest" → 命中2条 ✅
  - 薄弱领域: "AI security vulnerability" → 命中1条 ✅
  - 新探索: "emerging LLM architecture" → 命中0条 ❌
  - 替换固化: "AI agent tools" → "autonomous agent benchmark" → 命中1条 ✅
- 新鲜度: 73% (与前日内容不重复比例)
- 建议: 下次保留"AI security vulnerability"，替换"emerging LLM architecture"
```

### 动态调整限制
- 动态query数量固定为5条，不超过总query的1/3
- 每条动态query最多连续使用3天，之后强制替换
- Base query保持稳定，确保领域覆盖基线
- 动态调整仅影响搜索关键词，不影响筛选和验证标准
