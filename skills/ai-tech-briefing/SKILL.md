# AI科技资讯简报

收集并验证AI科技领域资讯，输出高质量中文简报。

## 核心原则

- **一手来源优先**：官方公告、官方文档、论文、标准组织、安全机构、GitHub release/changelog
- **交叉验证**：每条重要信息至少2个独立来源比对
- **来源审查**：对营销号、转载站、未署名内容降权或剔除
- **实际验证**：打开并检查来源链接可访问性，核对发布日期、版本号、功能描述等
- **冲突处理**：标注冲突点、优先采信依据和纠错结论
- **未确认内容**：明确标注"未确认/待观察"

## 覆盖领域

- AI代理（AI Agent）
- 人工智能（大模型、AI应用）
- 开发者工具（API、SDK、IDE插件等）
- 网络安全（漏洞、安全事件、防护方案）
- 科技产品与基础设施

## 执行流程

### 1. 信息收集
使用 search_web 搜索过去24小时内的相关资讯，关键词覆盖上述领域。

### 2. 信息验证
对每条重要信息：
- 使用 fetch_web 打开来源链接，验证可访问性
- 核对发布日期、版本号、功能描述等关键事实
- 搜索其他独立来源进行交叉验证
- 对开发者工具，检查GitHub仓库的release/issue/changelog

### 3. 可信度评级
- 🟢 **高可信**：官方来源 + 多源验证
- 🟡 **中等可信**：有官方来源但未完全验证
- 🔴 **低可信/待观察**：来源单一或无法验证

### 4. 输出简报

#### 一、重要新闻（5-8条）
每条包含：
- 核心结论（1-2句话）
- 可信度评级
- 已核验来源链接（至少1个一手来源）
- 交叉验证结果（简要说明验证情况）
- 是否实测及测试方式（如适用）

#### 二、值得学习的新技能/概念（2-3个）
每个包含：
- 简明解释（是什么）
- 实践建议（怎么用）

#### 三、信息获取与验证报告
- 信息获取来源列表
- 筛选掉/修正掉的可疑信息（简要说明原因）
- 验证过程中遇到的问题及解决方法

### 5. 保存简报
将完整简报保存为 Markdown 文件，命名格式：`AI科技简报_YYYYMMDD.md`

## 边界情况处理

- **链接无法访问**：标注"链接已失效"，寻找替代来源
- **信息冲突**：列出不同来源的说法，说明优先采信哪个及理由
- **无法验证**：明确标注"未确认/待观察"，不传播未经验证的断言
- **信息过少**：扩大搜索范围或时间窗口，确保至少有5条可验证的新闻
