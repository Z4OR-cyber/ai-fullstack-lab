# Agent全流程自动化工作流引擎

将多Agent实战中验证的通用模式整合为统一方法论。无论领域（金融/科技/自媒体/安全），任何自动化工作流都遵循相同的七层架构，每层有标准化的设计原则和质量保障机制。

## 七层架构

```
触发层 → 采集层 → 处理层 → 验证层 → 输出层 → 交付层 → 运维层
```

### 1. 触发层 — 何时启动

**三种触发模式：**
- **定时触发**：Calendar日程 + rrule重复规则，适合周期性任务
- **事件触发**：用户需求/热点事件/异常信号，适合响应式任务
- **手动触发**：用户明确指令，适合一次性任务

**Calendar设置规范：**
- summary用动作短语（如"生成每日行情简报"）
- description是工单：任务目标+执行步骤+产出要求+脚本路径+存放目录
- dtstart避免整点（用15:35而非15:00），降低并发竞争
- time_range弹性窗口：未指定时间±30min，大致时段±10min，具体时间±5min
- rrule只设freq/interval/count/until，让系统从dtstart推导时间

### 2. 采集层 — 从哪获取数据

**多源采集原则：**
- 至少2个独立数据源
- 不同源命名差异是数据缺失的首要原因——建立别名映射表
- 别名重叠时自动去重，保留标准名

**搜索Query策略：**
- 全中文query → CSDN/知乎为主，一手来源极少
- 中英文混合query → 命中官方/权威站点
- 建议：每个方向1条中文+1条英文query

**来源质量分层：**
| 层级 | 类型 | 示例 |
|------|------|------|
| Tier 1 | 官方一手 | 官网公告/财报/论文/法规原文 |
| Tier 2 | 权威二手 | 主流媒体/行业报告 |
| Tier 3 | 聚合 | 技术博客/社区讨论 |

**工具输出落盘：**
- 搜索/抓取/工具调用的完整输出写入文件
- 对话中只传结构化摘要，不传原文

### 3. 处理层 — 如何加工

**Token优化八条（贯穿全流程）：**
1. 工具输出落盘，对话只传摘要
2. 结构化输出（JSON Schema替代自然语言长文）
3. 命令链式化（短命令替代长命令）
4. Token预算意识（system prompt最短化，条件加载详情）
5. 批处理优先（多个独立小任务合并为一次LLM调用）
6. 缓存复用（相同query 24h内不重复搜索）
7. 摘要替代全文（历史上下文用摘要传递）
8. 分级调用（简单任务用便宜模型，复杂任务才用贵模型）

**批处理实战：**
- 逐页/逐条调LLM → 每N条合并批量调用
- 适用：extract/summarize/classify等无状态处理
- 实测：LLM调用降67%，信息密度不变

### 4. 验证层 — 如何确保质量

**多源交叉验证：**
- 数据采集≥2个来源
- 标记分歧数据
- 偏差>5%标记⚠️待验证
- 取中位数或多数一致值
- 跨日验证：连续2天数据一致→可信

**冲突处理：**
- 以多源一致结果为准
- 优先采信原始来源（官网、公告、论文、法规原文）

**合规检查（内容类工作流）：**
- 发布前必查违禁词
- 常见踩坑：绝对化用语、虚假承诺、医疗用语、导流用语

### 5. 输出层 — 如何格式化

**Gene蒸馏压缩（通用输出格式）：**

将冗长输出压缩为四段式Gene格式，保留核心决策逻辑：

```
## Keywords    ← 触发关键词（逗号分隔）
## Summary     ← 一句话目标+约束
## Strategy    ← 核心逻辑（编号列表，保留具体数据锚点）
## AVOID       ← 禁止事项（bullet list）
```

**蒸馏原则：**
- 保留：具体数据、决策逻辑、验证过的结论、禁止事项
- 砍掉：模板化描述、重复说明、背景科普、执行过程描述
- 蒸馏后必须实际运行验证决策逻辑无损
- 实测压缩率76%-83%

### 6. 交付层 — 如何分发

**四通道同步：**
| 通道 | 用途 | 特点 |
|------|------|------|
| 项目文件空间 | 即时协作 | 所有项目成员可见 |
| notify推送 | 即时通知 | 主agent解读后回复用户 |
| GitHub仓库 | 版本控制 | 公开访问，commit追踪 |
| EvoMap/虾评 | 社区共享 | 语义搜索+评分+评测 |

**版本管理：**
- 每次更新递增版本号
- 新建版本文件而非原地覆盖

### 7. 运维层 — 如何保障可靠

**三层防御体系：**
1. **预防层**：追溯根因并消除，不满足于手动纠正
2. **监测层**：定期检查关键指标，趋势恶化时预警
3. **应急层**：快速止损并修复

**错误处理规范：**
- 先读错误信息，不盲目重试
- 同一工具同一参数最多重试1次
- 失败2次后换策略（换工具/换参数/换方法）

**自动Debug流程：**
1. 错误捕获：记录错误信息、上下文、参数
2. 自动诊断：匹配已知错误模式
3. 自动修复：超时→重试→换策略；认证→检查凭证；参数→对照文档
4. 知识沉淀：修复成功→更新经验文件；重复出现→提升到通用手册

**弹性调度：**
- 设置time_range窗口避免整点高峰
- 非整点执行成功率更高（实测70%→90%+）

## 全流程实战案例

### 案例1：金融行情推送
```
触发层: Calendar每日15:35（交易日）+ time_range ±5min
采集层: 多源行情API（≥2来源）+ 别名映射
处理层: 数据校验+三段式分析
验证层: 交叉验证偏差>5%标记⚠️ + 跨日验证
输出层: Gene蒸馏压缩报告（<1500字节）
交付层: notify推送 + 项目文件存档
运维层: 弹性调度 + 失败重试1次 + 成功率统计
```

### 案例2：AI科技简报
```
触发层: Calendar每日08:00
采集层: 15条query搜索（中英文混合）+ 来源分层
处理层: 批处理事实抽取 + Token优化
验证层: 单域名上限3条 + 多源一致验证
输出层: 5-8条简报 + 来源验证报告
交付层: notify推送 + 文件落盘
运维层: 搜索缓存24h + 模型路由降成本
```

### 案例3：自媒体内容创作
```
触发层: 用户需求/热点事件
采集层: 热搜榜+爆款分析+账号诊断
处理层: 标题生成+正文创作+批量文案
验证层: 违禁词检查 + 爆款四要素评分
输出层: 多平台改写适配
交付层: 多平台发布 + 项目文件同步
运维层: 话题追踪 + 数据复盘 + 策略调整
```

## 设计新工作流的步骤

1. **明确目标**：这个工作流要自动产出什么？
2. **分层设计**：逐层填写七层架构，每层选择对应的标准机制
3. **识别复用**：哪些层可以直接套用已有技能/脚本？
4. **设置质量门控**：在验证层定义什么情况算"通过"
5. **配置触发**：Calendar日程 + time_range弹性窗口
6. **小规模验证**：先手动跑1-2次，确认每层产出符合预期
7. **上线运维**：记录成功率，持续优化瓶颈层
