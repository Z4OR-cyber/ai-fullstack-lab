# Calendar + CodeAct 定时任务自动化模式

提供一套标准的定时任务自动化架构，从Calendar触发到结果推送全链路覆盖，含可靠性保障机制。实战验证：每日行情推送连续运行20+天，成功率从70%提升至90%+。

## 标准架构

```
Calendar触发 → 独立session读取工单 → CodeAct脚本执行 → notify推送结果 → 主agent解读
```

## Calendar设置规范

### summary
用动作短语描述任务，如"生成每日行情简报"、"每周投资组合复盘"。

### description（工单）
写给执行session的工单，需包含：
- 任务目标
- 执行步骤
- 产出要求
- 脚本路径（如有）
- 存放目录

### dtstart（执行时间）
- 避免整点，用非整点时间（如15:35而非15:00）降低并发竞争
- 用户指定具体时间按用户设置

### time_range（弹性调度窗口）
提高执行成功率，避免整点高峰排队：
- 用户未指定时间：±30min
- 指定大致时段：±10min
- 指定具体时间：±5min

### rrule（重复规则）
- 常规重复只设freq/interval/count/until
- 不要额外填byhour/byminute/byday，让系统从dtstart推导

## CodeAct脚本规范

### 脚本存放
放在agent工作目录下，如 `./codeact/scripts/`

### 脚本职责
1. 数据采集（多源）
2. 数据处理与校验
3. 格式化输出
4. 通过notify推送给主agent

## 可靠性保障机制

### 1. 多源交叉验证
- 数据采集≥2个来源
- 标记分歧数据
- 偏差>5%标记⚠️待验证
- 取中位数或多数一致值
- 跨日验证：连续2天数据一致→可信

### 2. 别名映射
不同数据源命名差异是数据缺失的首要原因：
- 建立别名映射表（如"电力设备"≠"电网设备"）
- 别名重叠时自动去重，保留标准名

### 3. 错误处理
- 脚本失败时记录错误信息
- 连续失败时检查数据源可用性
- 数据缺失时标记⚠️而非中断
- 同一工具同一参数最多重试1次

### 4. 弹性调度
- 设置time_range窗口避免整点高峰
- 非整点执行成功率更高

## 实战经验

### 成功案例：每日行情推送
- 执行时间：交易日15:35（弹性15:30-15:45）
- 脚本：market_briefing.py
- 内容：A股指数+持仓板块+海外市场+黄金
- 多源交叉验证：天天基金+蛋卷+CME
- 迭代历程：v1(70%)→v2(80%)→v3(90%+)

### 关键教训
1. 非整点执行：整点高峰容易排队延迟，偏移5-10分钟成功率更高
2. 别名映射：不同数据源命名差异是数据缺失的首要原因
3. 渐进式增强：先跑通基础流程，再逐步增加可靠性机制
4. notify而非直接回复：脚本结果通过notify推送给主agent解读，比直接回复用户更灵活

## 适用场景

- 每日行情/新闻推送
- 定期数据采集与报告生成
- 周期性监控与预警
- 定时复盘与状态同步
- 任何需要定时自动执行的任务
