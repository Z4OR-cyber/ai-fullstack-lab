# 提示词工程方法论

系统化的提示词设计、优化与压缩方法论，源自6个Agent实战经验+行业最佳实践。

## 工作流程

### 1. 判断需求类型

| 需求 | 适用方法 |
|------|---------|
| 从零写System Prompt | 8层分层架构（第2节） |
| 优化已有Prompt | 迭代优化工作流（第7节） |
| 压缩Token/减少上下文 | Gene蒸馏法（第5节） |
| 结构化任务指令 | 六大框架选一（第3节） |
| Agent多步任务 | Agent实战模式（第4节） |
| 多源信息验证 | 交叉验证模板（第6节） |

### 2. 八层分层架构

System Prompt分为静态层（全局固定）和动态层（每次组装）：

```
静态层：身份定义 → 能力边界 → 行为规范 → 输出格式
动态层：任务指令 → RAG上下文 → 对话历史 → 用户输入
```

**关键统计**（生产级Prompt分析）：
- Directive出现率86.7%，Context 56.2%，Output Format 39.7%
- 90%指令使用祈使句
- 关键指令放在开头和结尾（"黄金区域"）
- JSON输出指定字段名+描述，比只说"输出JSON"遵循率高58%

### 3. 六大框架速查

| 框架 | 适用场景 | 核心要素 |
|------|---------|---------|
| **CRISPE** | 通用复杂任务 | Capacity/Role/Insight/Statement/Personality/Experiment |
| **COSTAR** | 结构化输出 | Context/Objective/Style/Tone/Audience/Response |
| **RTF** | 简单快速 | Role/Task/Format |
| **DFT** | 详细指令 | Directive/Examples/Format |
| **BROKE** | Agent推理 | Background/Role/Objective/Key Result/Evolve |
| **ICIO** | 指令清晰 | Instruction/Context/Input/Output |

选择原则：简单任务用RTF，需要推理用BROKE，需要风格控制用COSTAR。

### 4. Agent实战提示词模式

**结论先行模式**：
```
先输出核心结论（1-2句）
再补充数据依据和逻辑链
最后标注风险/不确定性
```

**多步推理模式**：
```
Step 1: [拆解问题]
Step 2: [收集信息]
Step 3: [分析判断]
Step 4: [给出建议]
```

**自我验证模式**：
```
给出答案后，自问：
1. 数据来源是否可靠？
2. 逻辑链是否完整？
3. 是否有反例或边界情况？
4. 结论是否过度推断？
```

### 5. Gene蒸馏法（Token压缩）

将冗长经验文档压缩为紧凑Gene格式，实测token降低76%+：

```
Keywords: [3-5个关键词]
Summary: [一句话核心结论]
Strategy:
  - [可执行策略1]
  - [可执行策略2]
AVOID:
  - [要避免的坑1]
  - [要避免的坑2]
```

压缩原则：
- 砍掉模板化描述和重复说明
- 保留决策逻辑和判断条件
- 用动词开头的祈使句替代解释性文字
- 详细数据移入references/文件，正文只留指针

### 6. 多源交叉验证模板

```
信息源A报告：[摘要]
信息源B报告：[摘要]
信息源C报告：[摘要]

交叉验证结果：
- 一致点：[多源确认的事实]
- 分歧点：[来源冲突，标注各方]
- 缺失点：[无来源覆盖]
- 置信度：[高/中/低] + 依据
```

### 7. 迭代优化工作流

1. **基线测试**：用5-10个典型case跑当前Prompt，记录问题
2. **分类归因**：漏触发→改description；执行偏差→改正文指令；格式错误→加示例
3. **单变量修改**：一次只改一个方面，改完立即测试
4. **泛化检查**：修改是否覆盖一类问题而非仅修当前case
5. **精简优先**：如果指令太多导致注意力分散，先删减而非新增

### 8. 十大反模式

1. ❌ 模糊限定词（"适当""合理"）→ 改为具体标准
2. ❌ 重复系统已有能力 → 删掉
3. ❌ 所有逻辑塞description → description只管触发，执行放正文
4. ❌ 为特殊case写if-else → 想通用规则覆盖
5. ❌ 只说"输出JSON" → 指定字段名和字段描述
6. ❌ Prompt过长无重点 → 关键指令放黄金区域
7. ❌ 用疑问句而非祈使句 → "解析X"比"你能解析X吗"清晰
8. ❌ 硬编码用户名/数据 → 用变量占位
9. ❌ 堆砌"必须/严禁" → 解释原因更有效
10. ❌ 不做版本管理 → 每次修改记录变更日志

### 9. 输出规范

帮用户编写或优化Prompt后，输出：
1. **完整Prompt文本**（可直接复制使用）
2. **设计说明**（用了哪个框架、为什么这样分层）
3. **改进对比**（如有原始版本，列出关键改动及原因）
4. **使用建议**（适用场景、预期效果、注意事项）
