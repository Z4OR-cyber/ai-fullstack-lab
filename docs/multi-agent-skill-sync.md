# 多 Agent 技能同步方法论

> 核心理念：技能是可复用的能力封装，不绑定特定 Agent 身份。多 Agent 通过项目协作自然产生技能流动。

---

## 一、为什么需要技能同步

### 问题
- 多个 Agent 各自积累经验，但缺乏共享机制
- 相同问题在不同 Agent 间重复踩坑
- 技能迭代分散，无法形成版本管理
- 缺乏质量评估和进化反馈

### 解决方案
通过项目协作空间作为媒介，让技能在 Agent 间自然流动，再统一整理同步到三个平台：

| 平台 | 角色 | 特点 |
|------|------|------|
| GitHub | 版本管理 + 开源协作 | 完整文件结构，支持 fork/PR |
| EvoMap | 质量评估 + 进化反馈 | GDI 评分，社区对标，自动 promote |
| Coze 商店 | 面向用户分发 | 终端用户可直接安装使用 |

---

## 二、项目协作空间作为媒介

### 工作机制

```
项目群聊（多 Agent + 用户）
    │
    ├── 实时协作：群聊讨论、@指定Agent、引用消息
    ├── 文件共享：项目文件空间，所有成员可见
    ├── 任务分配：用户统一调度，各Agent按角色承接
    │
    └── 技能自然流动
         ├── Agent A 完成任务 → 提炼经验 → 上传项目文件
         ├── Agent B 发现可用 → 复用到自己的任务
         ├── Agent C 补充优化 → 迭代更新
         └── 统一整理 → 去Agent身份 → 三平台同步
```

### 关键设计

1. **去身份化整理**：技能整理时不保留任何 Agent 名称、ID 或角色信息。只保留方法论、工具链和验证数据
2. **经验分类**：
   - 通用经验：所有 Agent 都适用的方法论（Token优化、搜索策略等）
   - 领域技能：特定领域的专业能力（金融分析、自媒体创作等）
   - 基础设施：跨领域的框架性能力（自进化机制、日历自动化等）
3. **验证驱动**：每条经验必须附带验证数据（压缩率、成功率、调用次数等）

## 三、三平台同步流程

### 3.1 GitHub 同步
- 仓库结构：`skills/` 放技能实现，`experiences/` 放通用经验，`docs/` 放方法论
- 每次更新先在本地验证，再 git push
- 多 Agent 并行推送时用 `git fetch + merge` 合并

### 3.2 EvoMap 发布
- 格式：Gene（轻量能力描述）+ Capsule（完整实现）+ EvolutionEvent（进化记录）
- GDI 评分维度：call_count、reuse_count、trigger_text 覆盖度、summary 质量、validation 严谨度
- 发布约束：
  - Gene 必须含 strategy 字段（≥2步数组）
  - validation 禁用 Shell 操作符（`;` `||` `&&` `>` `<` `&`）
  - validation 不能是 trivial（如直接 return true）
  - asset_id 必须是 sha256 哈希
- 优化策略：trigger_text 从简单关键词升级为场景式+条件式信号

### 3.3 Coze 技能商店
- 技能先发布到「我的技能」
- 上架公开商店需开通商户账户
- 提交审核周期约 5 天
- 平台与开发者分成 7:3

## 四、技能质量评估框架

### 4.1 GDI 四维优化
1. **trigger_text 覆盖度**：从简单关键词升级为场景式信号（如 `hollow_success, capability_gap, self_optimization_missed`）
2. **summary 精准度**：一句话说清解决什么问题+约束条件
3. **strategy 完整性**：≥2步数组，每步含具体数据锚点
4. **validation 严谨度**：用 Math 函数验证而非 trivial 命令

### 4.2 经验沉淀标准
- 必须在实际任务中验证有效
- 附带量化数据（压缩率、调用次数、成功率等）
- 去除 Agent 个人信息，只保留方法论
- 标注适用场景和前置条件

## 五、自进化机制

### 每日社区学习
- 每日定时扫描 EvoMap 社区新增资产
- 对标 Top10 高分资产，分析 GDI 差距
- 识别可吸纳的高需求领域和模式

### 资产迭代
- 低 GDI 资产识别优化点（trigger_text、summary、strategy）
- 发布优化版本，保留历史版本
- 定期清理 Carbon Tax 过高的低质量资产

### 协作进化
- 多 Agent 各自贡献领域经验
- 统一整理去身份化后同步
- EvoMap 平台提供质量反馈循环
