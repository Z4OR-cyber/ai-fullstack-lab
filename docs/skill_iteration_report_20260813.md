## 二、agent-ops-toolkit 迭代详情

### 2.1 新增模块清单

#### 模块五：7层自动化工作流引擎
- **来源**: 投资理财小豆整合分析
- **7层架构**: 触发层 → 采集层 → 处理层 → 验证层 → 输出层 → 交付层 → 运维层
- **关键特性**:
  - 每层有明确输入/输出和质量门控
  - 层间数据流伪代码定义
  - 质量门控表：5个关键门控点，不通过时有降级处理策略
  - 适用于定时简报、资产发布、记忆GC等所有自动化场景

#### 模块六：跨技能健康仪表盘（增强版）
- **一站式检查**: 记忆容量 + Token消耗 + EvoMap资产状态 + 知识库页数 + 定时任务 + 技能状态
- **可视化输出**: ASCII仪表盘格式，含进度条和状态标记
- **健康度评分**: 6维度加权评分，≥80分🟢，60-79🟡，<60🔴
- **评分规则**: 每个维度有明确的扣分规则和权重

#### 模块七：自适应调度建议
- **数据采集**: 记录任务类型、时间、耗时、成功率、Token消耗、重试次数
- **时间窗口推荐**: 基于近30天数据推荐最优3个时间窗口
- **失败模式分析**: 识别高频失败时段和原因
- **资源冲突检测**: 检测多任务集中时段，建议错峰执行
- **动态调整**: 连续3次失败建议调整、Token上升建议压缩

#### 模块八：Gene蒸馏法文档治理
- **来源**: 投资理财小豆实践，76%压缩率
- **三轮蒸馏**: 去冗余(60%) → 抽骨架(35%) → 炼精华(24%)
- **分层保留**: 核心层(不压缩) + 支撑层(压缩为引用) + 背景层(概括/删除)
- **质量保障**: 可执行指令100%保留，功能完整性检查
- **与GC区别**: GC删除无用内容(10-30%压缩)，蒸馏压缩有用内容(70-80%压缩)

## 三、ai-tech-briefing 迭代详情

### 3.1 新增模块清单

#### 模块六：OG元数据提取验证
- **设计目标**: 作为来源验证补充手段，减少全文抓取的Token消耗
- **提取字段**: og:title, og:description, og:type, og:site_name, og:url, og:published_time, og:author, og:image
- **验证规则**: 5项OG字段验证规则，检测标题篡改、时效造假、镜像站等
- **快速预筛**: OG完整→全文抓取，OG部分缺失→降级处理，OG缺失→剔除
- **Token节省**: 预筛可过滤30-50%低质量候选，OG数据<500字节远小于全文
- **集成方式**: 作为原步骤3（信息验证）的前置快速预筛

#### 模块七：周度/月度摘要模式
- **三种模式**: 每日(5-8条/6-10KB) / 周度(10-15条/12-18KB) / 月度(15-20条/20-30KB)
- **周度摘要**: 聚合7天日报，识别升温/持续/降温/新增话题，提供发展脉络时间线
- **月度摘要**: 聚合30天日报+4期周报，月度十大新闻、趋势热力图、概念演化追踪
- **触发方式**: 手动请求 + 定时触发（每周一/每月1日）
- **数据来源**: 基于每日简报存档聚合，无需重新搜索

#### 模块八：趋势追踪功能
- **话题指纹**: 主要实体 + 动作类型 + 领域 + 关键词集合
- **跨天匹配**: 强匹配(同实体+同动作) / 中匹配(同实体+不同动作) / 弱匹配(关键词Jaccard>0.6)
- **5个分析维度**: 出现频率、热度变化、信息演化、来源扩散、领域扩散
- **趋势报告**: 持续热点(含时间线)、升温话题(含建议关注度)、新兴话题(待观察)
- **数据存储**: briefing_archive/ 下按daily/weekly/monthly/trends组织

#### 模块九：动态Query策略
- **前日分析**: 已覆盖话题、主要实体、领域平衡性、来源分布、信息缺口
- **6条调整规则**: 连续出现→深度query、占比低→增加query、来源集中→排除、无新概念→前沿探索、升温话题→跟进、未覆盖→重构query
- **动态query生成**: 跟进话题(2条) + 薄弱领域(2条) + 新探索(1条) = 最多5条
- **效果评估**: 每条query记录候选数、选中数、新鲜度、来源多样性
- **限制**: 动态query≤5条(总1/3)，每条最多连续3天，Base query保持稳定

## 四、evomap-asset-manager 迭代详情

### 4.1 API认证方式更新

#### 变更内容
- **原方式（已废弃）**: 在POST请求体中传递 `node_secret`
- **新方式（当前规范）**: 使用 `Authorization: Bearer <node_secret>` 请求头

#### 更新要点
- 新增"API认证方式"独立模块，明确认证规范
- 标注废弃方式（❌），防止误用
- 新增认证安全规则：永不暴露、仅头部传递、凭证隔离、密钥轮换(90天)
- 常见错误处理表新增 HTTP 401 认证失败 和 flagged 状态条目

**注意**: 经核查，原SKILL.md中发布和撤销流程已使用Bearer Token头部认证，本次迭代将其提取为独立模块并补充安全规则，同时明确标注废弃方式。

### 4.2 新增模块清单

#### 模块：与 multi-platform-publishing-engine 协同
- **协同架构**: 资产创作 → 隐私清洗(本技能) → EvoMap发布(本技能) + 其他平台分发(发布引擎)
- **职责分工表**: 7项职责明确划分本技能与发布引擎的边界
- **协同工作流**: 
  - 场景1：新资产多平台发布（清洗→EvoMap先发→委托其他平台→汇总）
  - 场景2：资产撤销同步（EvoMap撤销→通知发布引擎同步撤销）
- **数据交换格式**: 统一资产描述JSON
- **注意事项**: 隐私清洗优先、EvoMap先发、状态同步、撤销联动

#### 模块：资产健康检查
- **全量扫描**: 查询所有状态资产，统计promoted/candidate/quarantined/flagged/revoked
- **问题诊断**: 6类异常状态诊断（validation失败/内容不完整/隐私残留/用户举报/内容过时/链接失效）
- **修复建议**: 每类问题对应修复步骤和auto_fixable标记
- **健康检查报告**: ASCII可视化报告，含资产总览、问题详情、修复计划
- **自动修复**: 对auto_fixable=True的资产自动执行撤销→修复→重发流程
- **定期检查**: 每日快检(仅查异常数量) + 每周全检(完整报告+自动修复) + 触发式检查(发布后)

#### 模块：批量操作安全确认机制
- **3级确认体系**:
  - Level 1 预览确认：所有批量操作必须预览资产列表
  - Level 2 风险评估：撤销/修改操作自动评估风险等级
  - Level 3 二次确认：高风险操作需输入"CONFIRM"确认
- **风险评估**: 高风险(批量撤销promoted>5个) / 中风险(同类>10个/有依赖) / 低风险
- **操作审计日志**: 记录操作者、时间、资产列表、风险等级、确认方式、结果
- **批量限制**: 发布(100个/次) / 撤销(50个/次) / 修复(50个/次) / 查询(不限)
- **紧急中止**: 可中止未执行批次，生成中止报告
