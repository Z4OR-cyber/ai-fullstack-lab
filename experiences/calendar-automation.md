# Calendar + CodeAct 定时任务自动化模式

## 一、适用场景

任何需要定时自动执行的任务：
- 每日行情/新闻推送
- 定期数据采集与报告生成
- 周期性监控与预警
- 定时复盘与状态同步

## 二、标准架构

```
Calendar触发 → 独立session读取工单 → CodeAct脚本执行 → notify推送结果 → 主agent解读
```

### 2.1 Calendar设置
- **summary**：动作短语，如"生成每日行情简报"
- **description**：写给执行session的工单，包含目标、步骤、产出要求
- **dtstart**：执行时间（避免整点，用非整点时间降低并发）
- **time_range**：弹性调度窗口（±5~30min），提高执行成功率
- **rrule**：重复规则（DAILY/WEEKLY等）

### 2.2 CodeAct脚本
- 脚本放在agent工作目录下（如`./codeact/scripts/`）
- 脚本内完成：数据采集→处理→格式化输出
- 输出通过notify推送给主agent

### 2.3 执行session职责
- 读取Calendar description中的工单
- 执行CodeAct脚本
- 将结果通过notify推送给主agent
- 主agent负责解读和通知用户

## 三、可靠性保障

### 3.1 弹性调度
- 设置time_range窗口，避免整点高峰排队
- 用户未指定时间：±30min
- 指定大致时段：±10min
- 指定具体时间：±5min

### 3.2 多源交叉验证
- 数据采集≥2个来源
- 标记分歧数据
- 偏差>5%标记⚠️待验证
- 取中位数或多数一致值

### 3.3 别名映射（数据处理）
- 不同数据源名称不一致时建立别名映射
- 示例："电力设备"≠"电网设备"→建立SECTOR_ALIASES
- 别名重叠时自动去重

### 3.4 错误处理
- 脚本失败时记录错误信息
- 连续失败时检查数据源可用性
- 板块/数据缺失时标记⚠️而非中断

### 成功案例：每日行情推送

- 迭代历程：
  - v1：基础版，成功率70%

### 关键教训
1. **非整点执行**：整点高峰容易排队延迟，偏移5-10分钟成功率更高
2. **别名映射**：不同数据源命名差异是数据缺失的首要原因
3. **渐进式增强**：先跑通基础流程，再逐步增加可靠性机制
4. **notify而非直接回复**：脚本结果通过notify推送给主agent解读，比直接回复用户更灵活
