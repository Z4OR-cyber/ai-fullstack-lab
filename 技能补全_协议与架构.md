## 模块1：MCP（模型上下文协议）— 5题

### 知识点总览

**MCP（Model Context Protocol）** 是 Anthropic 于 2024 年提出的开放协议，旨在标准化 LLM 应用与外部工具/数据源之间的通信。其核心设计如下：

```
┌─────────────────────────────────────────────────┐
│                  MCP 架构                        │
│                                                  │
│  ┌──────────┐    JSON-RPC 2.0    ┌──────────┐  │
│  │  Client  │ ◄─────────────────► │  Server  │  │
│  │ (LLM侧)  │    stdio / SSE      │ (工具侧)  │  │
│  └──────────┘                      └──────────┘  │
│       │                                  │       │
│   发现能力                          注册能力       │
│   调用工具                          处理请求       │
│                                                  │
│  三种能力：Tool（工具）/ Resource（资源）/ Prompt  │
│  传输层：stdio（本地）/ SSE（远程）/ WebSocket     │
└─────────────────────────────────────────────────┘
```

**与 Function Calling 的核心区别**：
- Function Calling 是各厂商私有协议（OpenAI、Claude 各自定义格式）
- MCP 是跨厂商标准：同一个 MCP Server 可被任何支持 MCP 的 Client 使用
- MCP 的消息格式统一为 JSON-RPC 2.0，降低了集成成本

### 第482题：最小MCP Server —— 注册2个工具，处理JSON-RPC请求

#### 知识点讲解

**JSON-RPC 2.0 协议**是 MCP 的消息基础。每条消息包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| `jsonrpc` | 协议版本，固定 `"2.0"` | `"2.0"` |
| `id` | 请求标识（整数或字符串），用于匹配响应 | `1` |
| `method` | 方法名 | `"tools/list"` |
| `params` | 参数对象 | `{"name": "add", ...}` |

MCP Server 的核心方法：
- `initialize`：握手，返回协议版本和服务器信息
- `tools/list`：列出所有已注册工具
- `tools/call`：调用指定工具，传入参数

**Tool 声明格式**：每个工具包含 `name`（唯一标识）、`description`（供 LLM 理解用途）、`inputSchema`（JSON Schema 格式的参数定义）。

```python
import json

# ============================================================
# 第482题：最小MCP Server
# 实现一个注册了2个工具的MCP Server，完整处理JSON-RPC 2.0请求
# ============================================================

class MCPServer:
    """最小MCP Server实现
    
    架构：
      - tools: 工具注册表 {name -> tool_definition}
      - handle_request(): JSON-RPC 2.0 请求分发器
      
    生命周期：
      1. Client 发送 initialize 请求 -> Server 返回协议版本和能力声明
      2. Client 发送 tools/list -> Server 返回工具列表
      3. Client 发送 tools/call -> Server 执行工具并返回结果
    """
    
    def __init__(self, name="mini-mcp-server", version="1.0.0"):
        """初始化MCP Server
        
        参数:
            name: 服务器名称（在initialize响应中返回给Client）
            version: 服务器版本
        """
        self.name = name
        self.version = version
        self.tools = {}       # 工具名 -> 工具定义（含handler）
        self.resources = {}   # 资源URI -> 资源定义（第3题使用）
        self.prompts = {}     # 提示词名 -> 提示词定义（第4题使用）
    
    def register_tool(self, name, description, input_schema, handler):
        """注册一个工具
        
        参数:
            name: 工具名（唯一标识，如 "add"）
            description: 工具描述（供LLM理解工具用途，决定何时调用）
            input_schema: JSON Schema格式参数定义
                         例: {"type":"object","properties":{"a":{"type":"number"}},"required":["a"]}
            handler: 处理函数，接收dict参数返回结果
        """
        self.tools[name] = {
            "name": name,
            "description": description,
            "inputSchema": input_schema,
            "handler": handler
        }
    
    def handle_request(self, request):
        """处理单个JSON-RPC 2.0请求，返回JSON-RPC 2.0响应
        
        这是Server的核心入口：解析method字段，路由到对应处理器。
        所有响应遵循JSON-RPC 2.0格式。
        """
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        
        # 1. initialize —— 初始化握手
        # Client连接后首先发送此请求，Server返回协议版本和自身能力
        if method == "initialize":
            return {
                "jsonrpc": "2.0",
                "id": req_id,
                "result": {
                    "protocolVersion": "2024-11-05",
                    "serverInfo": {"name": self.name, "version": self.version},
                    "capabilities": {"tools": {}, "resources": {}, "prompts": {}}
                }
            }
        
        # 2. tools/list —— 列出所有可用工具
        # 返回工具元数据列表（不含handler，handler是Server内部实现）
        if method == "tools/list":
            tool_list = []
            for t in self.tools.values():
                tool_list.append({
                    "name": t["name"],
                    "description": t["description"],
                    "inputSchema": t["inputSchema"]
                })
            return {"jsonrpc": "2.0", "id": req_id, "result": {"tools": tool_list}}
        
        # 3. tools/call —— 调用某个工具
        # params中包含工具名和调用参数
        if method == "tools/call":
            tool_name = params.get("name")
            arguments = params.get("arguments", {})
            if tool_name not in self.tools:
                # JSON-RPC标准错误码 -32601: Method not found
                return self._error(req_id, -32601, f"Unknown tool: {tool_name}")
            try:
                result = self.tools[tool_name]["handler"](arguments)
                # MCP工具调用结果用content数组包装，支持多种返回类型
                return {
                    "jsonrpc": "2.0", "id": req_id,
                    "result": {"content": [{"type": "text", "text": str(result)}]}
                }
            except Exception as e:
                # -32603: Internal error（工具执行出错）
                return self._error(req_id, -32603, f"Tool execution error: {e}")
        
        # 4. 未知方法
        return self._error(req_id, -32601, f"Method not found: {method}")
    
    def _error(self, req_id, code, message):
        """构造JSON-RPC 2.0错误响应
        
        JSON-RPC标准错误码:
          -32700: Parse error（JSON解析失败）
          -32600: Invalid Request
          -32601: Method not found
          -32602: Invalid params
          -32603: Internal error
        """
        return {"jsonrpc": "2.0", "id": req_id, "error": {"code": code, "message": message}}


# === 运行测试 ===
server = MCPServer("calc-server", "1.0.0")

# 注册工具1：加法计算器
server.register_tool(
    name="add",
    description="将两个数字相加",
    input_schema={
        "type": "object",
        "properties": {
            "a": {"type": "number", "description": "第一个数"},
            "b": {"type": "number", "description": "第二个数"}
        },
        "required": ["a", "b"]
    },
    handler=lambda args: args["a"] + args["b"]
)

# 注册工具2：字符串反转
server.register_tool(
    name="reverse",
    description="反转字符串",
    input_schema={
        "type": "object",
        "properties": {"text": {"type": "string", "description": "要反转的文本"}},
        "required": ["text"]
    },
    handler=lambda args: args["text"][::-1]
)

# 测试 initialize

assert init_resp["result"]["serverInfo"]["name"] == "calc-server"
assert init_resp["result"]["protocolVersion"] == "2024-11-05"
print(f"  握手成功: {init_resp['result']['serverInfo']}")

# 测试 tools/list

assert len(list_resp["result"]["tools"]) == 2
print(f"  工具列表: {[t['name'] for t in list_resp['result']['tools']]}")

# 测试 tools/call —— 加法

                                   "params": {"name": "add", "arguments": {"a": 3, "b": 7}}})
assert "10" in call_resp["result"]["content"][0]["text"]
print(f"  add(3, 7) = {call_resp['result']['content'][0]['text']}")

# 测试 tools/call —— 反转
rev_resp = server.handle_request({"jsonrpc": "2.0", "id": 4, "method": "tools/call",
                                  "params": {"name": "reverse", "arguments": {"text": "hello"}}})
assert "olleh" in rev_resp["result"]["content"][0]["text"]
print(f"  reverse('hello') = {rev_resp['result']['content'][0]['text']}")

# 测试错误处理
err_resp = server.handle_request({"jsonrpc": "2.0", "id": 5, "method": "tools/call",
                                  "params": {"name": "nonexistent", "arguments": {}}})
assert "error" in err_resp
assert err_resp["error"]["code"] == -32601
print(f"  错误处理: code={err_resp['error']['code']}, msg={err_resp['error']['message']}")

print("✅ 第482题 通过：最小MCP Server（注册2个工具，处理JSON-RPC请求）")
```

### 第483题：MCP Client —— 连接Server、发现工具列表、调用工具

#### 知识点讲解

**MCP Client** 是 LLM 应用侧的组件，负责与 MCP Server 通信。其核心职责：

1. **连接管理**：发起 `initialize` 握手，建立会话
2. **能力发现**：通过 `tools/list` 获取 Server 暴露的工具列表，供 LLM 决策
3. **工具调用**：将 LLM 的函数调用请求转发给 Server，获取结果返回给 LLM

Client 的设计要点：
- **状态管理**：维护会话状态（是否已初始化、会话ID）
- **错误处理**：Server 返回 error 时需要妥善处理，不能让 LLM 应用崩溃
- **结果解析**：Server 返回的 `content` 数组可能包含多种类型（text/image），需要正确解析

```python
import json
import uuid

# ============================================================
# 第483题：MCP Client
# 实现一个完整的MCP Client：连接Server、发现工具、调用工具
# ============================================================

class MCPServer:
    """复用第482题的Server实现"""
    def __init__(self, name="server", version="1.0.0"):
        self.name = name
        self.version = version
        self.tools = {}
    
    def register_tool(self, name, description, input_schema, handler):
        self.tools[name] = {"name": name, "description": description,
                            "inputSchema": input_schema, "handler": handler}
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        if method == "initialize":
            return {"jsonrpc": "2.0", "id": req_id, "result": {
                "protocolVersion": "2024-11-05",
                "serverInfo": {"name": self.name, "version": self.version},
                "capabilities": {"tools": {}}}}
        if method == "tools/list":
            tools = [{"name": t["name"], "description": t["description"],
                      "inputSchema": t["inputSchema"]} for t in self.tools.values()]
            return {"jsonrpc": "2.0", "id": req_id, "result": {"tools": tools}}
        if method == "tools/call":
            tool_name = params.get("name")
            arguments = params.get("arguments", {})
            if tool_name not in self.tools:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32601, "message": f"Unknown tool: {tool_name}"}}
            try:
                result = self.tools[tool_name]["handler"](arguments)
                return {"jsonrpc": "2.0", "id": req_id,
                        "result": {"content": [{"type": "text", "text": str(result)}]}}
            except Exception as e:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32603, "message": str(e)}}
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}


class MCPClient:
    """MCP Client实现
    
    职责：
      1. 连接Server并发起initialize握手
      2. 发现可用工具列表
      3. 调用指定工具并解析返回结果
    
    状态：
      - initialized: 是否已完成握手
      - server_info: Server的名称和版本
      - available_tools: 已发现的工具列表
      - session_id: 本Client的唯一标识
    """
    
    def __init__(self, server):
        """初始化Client，传入要连接的Server实例
        
        参数:
            server: MCPServer实例（实际中通过Transport层连接）
        """
        self.server = server
        self.server_info = None       # 握手后存储Server信息
        self.available_tools = []     # 工具发现结果
        self.session_id = str(uuid.uuid4())[:8]  # 模拟会话ID
        self.initialized = False      # 握手状态标记
    
    def connect(self):
        """发起initialize握手，建立与Server的连接
        
        返回: 完整的JSON-RPC响应
        异常: 如果Server返回error，抛出RuntimeError
        """
        resp = self.server.handle_request({
            "jsonrpc": "2.0", "id": 1, "method": "initialize",
            "params": {"clientInfo": {"name": "mcp-client", "version": "1.0"}}
        })
        if "error" in resp:
            raise RuntimeError(f"Connection failed: {resp['error']['message']}")
        self.server_info = resp.get("result", {}).get("serverInfo", {})
        self.initialized = True
        return resp
    
    def discover_tools(self):
        """发现Server暴露的可用工具列表
        
        前置条件: 必须先调用connect()
        返回: 工具元数据列表
        """
        if not self.initialized:
            raise RuntimeError("Client not initialized. Call connect() first.")
        resp = self.server.handle_request({"jsonrpc": "2.0", "id": 2, "method": "tools/list"})
        self.available_tools = resp.get("result", {}).get("tools", [])
        return self.available_tools
    
    def call_tool(self, name, arguments):
        """调用指定工具
        
        参数:
            name: 工具名（需在available_tools中存在）
            arguments: 调用参数dict
        返回: 工具执行结果（文本内容）
        异常: 工具不存在或执行出错时抛出RuntimeError
        """
        if not self.initialized:
            raise RuntimeError("Client not initialized. Call connect() first.")
        resp = self.server.handle_request({
            "jsonrpc": "2.0", "id": 3, "method": "tools/call",
            "params": {"name": name, "arguments": arguments}
        })
        if "error" in resp:
            raise RuntimeError(f"Tool call failed: {resp['error']['message']}")
        # 解析content数组，返回第一个文本内容
        content = resp["result"]["content"]
        return content[0]["text"] if content else None
    
    def list_tool_names(self):
        """返回已发现工具的名称列表"""
        return [t["name"] for t in self.available_tools]


# === 运行测试 ===
# 创建一个天气查询Server
server = MCPServer("weather-server", "2.0.0")
server.register_tool(
    "get_temp", "获取城市温度",
    {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]},
    lambda a: f"{a['city']}当前温度22°C"
)
server.register_tool(
    "get_humidity", "获取城市湿度",
    {"type": "object", "properties": {"city": {"type": "string"}}, "required": ["city"]},
    lambda a: f"{a['city']}当前湿度65%"
)

# Client连接流程

info = client.connect()
print(f"  连接成功: {info['result']['serverInfo']}")
print(f"  会话ID: {client.session_id}")

# 工具发现
tools = client.discover_tools()
print(f"  发现工具: {client.list_tool_names()}")
assert len(tools) == 2

# 工具调用
temp = client.call_tool("get_temp", {"city": "北京"})
print(f"  get_temp('北京') = {temp}")
assert "22°C" in temp

# 测试未初始化时调用工具
client2 = MCPClient(server)
try:
    client2.call_tool("get_temp", {"city": "上海"})
    assert False, "应该抛出异常"
except RuntimeError as e:
    assert "not initialized" in str(e)
    print(f"  未初始化保护: {e}")

print("✅ 第483题 通过：MCP Client（连接Server、发现工具列表、调用工具）")
```

### 第484题：MCP Resource Provider —— 暴露文件系统资源

#### 知识点讲解

**Resource（资源）** 是 MCP 的第二种能力类型，用于向 LLM 暴露数据源。与 Tool 的区别：

| 维度 | Tool（工具） | Resource（资源） |
|------|-------------|-----------------|
| 用途 | 执行动作（计算、查询） | 提供数据（文件、数据库内容） |
| 调用方式 | LLM 决定何时调用 | Client 主动读取 |
| 返回格式 | 执行结果 | 资源内容 |
| 示例 | 发邮件、查天气 | 读配置文件、获取数据库表结构 |

Resource 的两个核心方法：
- `resources/list`：列出所有可用资源（返回 URI、名称、描述、MIME类型）
- `resources/read`：读取指定 URI 的资源内容

**URI 设计**：MCP 使用 URI 标识资源，如 `file:///path/to/config.json`。URI scheme 决定了资源类型（`file://` 文件系统、`db://` 数据库等）。

```python
import json

# ============================================================
# 第484题：MCP Resource Provider
# 实现暴露文件系统资源的MCP Server，支持resources/list和resources/read
# ============================================================

class MCPServer:
    """基础Server（复用第482题）"""
    def __init__(self, name="server", version="1.0.0"):
        self.name = name
        self.version = version
        self.tools = {}
        self.resources = {}
        self.prompts = {}
    
    def register_tool(self, name, description, input_schema, handler):
        self.tools[name] = {"name": name, "description": description,
                            "inputSchema": input_schema, "handler": handler}
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        if method == "initialize":
            return {"jsonrpc": "2.0", "id": req_id, "result": {
                "protocolVersion": "2024-11-05",
                "serverInfo": {"name": self.name, "version": self.version},
                "capabilities": {"tools": {}, "resources": {}, "prompts": {}}}}
        if method == "tools/list":
            tools = [{"name": t["name"], "description": t["description"],
                      "inputSchema": t["inputSchema"]} for t in self.tools.values()]
            return {"jsonrpc": "2.0", "id": req_id, "result": {"tools": tools}}
        if method == "tools/call":
            tool_name = params.get("name")
            arguments = params.get("arguments", {})
            if tool_name not in self.tools:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32601, "message": f"Unknown tool: {tool_name}"}}
            result = self.tools[tool_name]["handler"](arguments)
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"content": [{"type": "text", "text": str(result)}]}}
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}


class MCPResourceServer(MCPServer):
    """扩展MCP Server，支持Resource能力
    
    Resource vs Tool:
      - Tool: LLM主动调用，执行动作
      - Resource: Client主动读取，获取数据
    
    新增方法:
      - register_resource(): 注册一个资源
      - resources/list: 列出所有资源
      - resources/read: 读取指定URI的资源内容
    """
    
    def register_resource(self, uri, name, description, mime_type, handler):
        """注册一个资源
        
        参数:
            uri: 资源URI（唯一标识，如 "file:///config.json"）
            name: 资源显示名称
            description: 资源描述
            mime_type: MIME类型（如 "application/json", "text/markdown"）
            handler: 无参函数，返回资源内容字符串
        """
        self.resources[uri] = {
            "uri": uri, "name": name, "description": description,
            "mimeType": mime_type, "handler": handler
        }
    
    def handle_request(self, request):
        """重写请求处理，增加Resource相关方法"""
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        
        # resources/list —— 列出所有可用资源
        if method == "resources/list":
            res_list = []
            for r in self.resources.values():
                res_list.append({
                    "uri": r["uri"], "name": r["name"],
                    "description": r["description"], "mimeType": r["mimeType"]
                })
            return {"jsonrpc": "2.0", "id": req_id, "result": {"resources": res_list}}
        
        # resources/read —— 读取指定URI的资源内容
        if method == "resources/read":
            uri = params.get("uri")
            if uri not in self.resources:
                # -32602: Invalid params（资源不存在）
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32602, "message": f"Resource not found: {uri}"}}
            content = self.resources[uri]["handler"]()
```

### 第485题：MCP Prompt Template —— 参数化提示词模板

#### 知识点讲解

**Prompt Template（提示词模板）** 是 MCP 的第三种能力类型，用于存储可复用的提示词模式。其核心价值：

1. **标准化**：将团队共享的最佳实践提示词固化到 Server 端
2. **参数化**：通过 `arguments` 动态填充模板变量
3. **版本管理**：Prompt 可以像代码一样版本化

MCP Prompt 的消息结构遵循对话格式：
```json
{
  "messages": [
    {"role": "user", "content": {"type": "text", "text": "..."}},
    {"role": "assistant", "content": {"type": "text", "text": "..."}}
  ]
}
```

两个核心方法：
- `prompts/list`：列出所有可用模板及其参数定义
- `prompts/get`：传入参数，获取填充后的完整消息序列

```python
import json

# ============================================================
# 第485题：MCP Prompt Template
# 实现参数化提示词模板Server，支持prompts/list和prompts/get
# ============================================================

class MCPServer:
    """基础Server"""
    def __init__(self, name="server", version="1.0.0"):
        self.name = name
        self.version = version
        self.tools = {}
        self.resources = {}
        self.prompts = {}
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        if method == "initialize":
            return {"jsonrpc": "2.0", "id": req_id, "result": {
                "protocolVersion": "2024-11-05",
                "serverInfo": {"name": self.name, "version": self.version},
                "capabilities": {"tools": {}, "resources": {}, "prompts": {}}}}
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}


class MCPPromptServer(MCPServer):
    """扩展MCP Server，支持Prompt Template能力
    
    Prompt Template 的核心概念：
      - 模板是一段可复用的提示词模式，带有参数化变量
      - 调用 prompts/get 时传入参数，Server返回填充后的完整消息序列
      - 消息序列遵循 {role, content} 格式，可直接送给LLM
    
    使用场景示例：
      - 代码审查提示词：传入代码和语言，返回审查指令
      - 翻译提示词：传入源文本和目标语言，返回翻译指令
      - Bug修复提示词：传入错误描述和堆栈信息，返回修复指令
    """
    
    def register_prompt(self, name, description, arguments, template_fn):
        """注册一个提示词模板
        
        参数:
            name: 模板名（唯一标识）
            description: 模板描述
            arguments: 参数定义列表
                       [{"name":"code","description":"待审查代码","required":True}]
            template_fn: 模板函数，接收参数dict，返回消息列表
        """
        self.prompts[name] = {
            "name": name, "description": description,
            "arguments": arguments, "template_fn": template_fn
        }
    
    def handle_request(self, request):
        """重写请求处理，增加Prompt相关方法"""
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        
        # prompts/list —— 列出所有可用模板
        if method == "prompts/list":
            prompt_list = []
            for p in self.prompts.values():
                prompt_list.append({
                    "name": p["name"], "description": p["description"],
                    "arguments": p["arguments"]
                })
            return {"jsonrpc": "2.0", "id": req_id, "result": {"prompts": prompt_list}}
        
        # prompts/get —— 获取填充参数后的完整消息序列
        if method == "prompts/get":
            prompt_name = params.get("name")
            args = params.get("arguments", {})
            if prompt_name not in self.prompts:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32602, "message": f"Prompt not found: {prompt_name}"}}
            # 调用模板函数，传入参数，获取消息列表
            messages = self.prompts[prompt_name]["template_fn"](args)
            return {"jsonrpc": "2.0", "id": req_id, "result": {"messages": messages}}
        
        return super().handle_request(request)


# === 运行测试 ===
```

### 第486题：MCP Transport层 —— stdio + SSE两种传输方式

#### 知识点讲解

**Transport（传输层）** 是 MCP 架构的最底层，负责在 Client 和 Server 之间传递 JSON-RPC 消息。MCP 定义了多种传输方式：

| 传输方式 | 适用场景 | 特点 |
|---------|---------|------|
| **stdio** | 本地进程间通信 | 简单可靠，Client启动Server子进程，通过stdin/stdout通信 |
| **SSE** | 远程通信 | 基于HTTP长连接，Server推送事件，Client发送请求 |
| **WebSocket** | 双向实时通信 | 全双工，适合高频交互场景（MCP 2.0草案） |

**stdio 传输流程**：
```
Client                 Transport(stdin/stdout)              Server
  |                          |                               |
  |-- write_request() ------>|                               |
  |                          |-------- read() -------------->|
  |                          |                               |-- handle_request()
  |                          |<------- send() ---------------|
  |<-- read_response() ------|                               |
```

**SSE 传输流程**：
```
Client                          Server
  |--- connect() --------------->|
  |--- send_request() ---------->| (HTTP POST)
  |                              |-- handle_request()
  |<--- send_response() ---------| (SSE event)
  |--- disconnect() ------------>|
```

```python
import json
from collections import deque

# ============================================================
# 第486题：MCP Transport层
# 实现stdio和SSE两种传输方式，模拟完整的消息传递流程
# ============================================================

class StdioTransport:
    """模拟stdio传输层
    
    实际中stdio传输：
      - Client启动Server作为子进程
      - Client通过子进程的stdin写入请求
      - Server从stdin读取请求，处理后写入stdout
      - Client从子进程的stdout读取响应
    
    这里用双向队列模拟管道缓冲区。
    """
    
    def __init__(self):
        # in_buffer: 模拟Server的stdin（Client写入请求）
        self.in_buffer = deque()
        # out_buffer: 模拟Server的stdout（Server写入响应）
        self.out_buffer = deque()
    
    def write_request(self, message):
        """Client端：将JSON-RPC请求写入Server的stdin"""
        self.in_buffer.append(json.dumps(message))
    
    def receive(self):
        """Server端：从stdin读取一条请求"""
        if self.in_buffer:
            return json.loads(self.in_buffer.popleft())
        return None
    
    def send(self, message):
        """Server端：将响应写入stdout"""
        self.out_buffer.append(json.dumps(message))
    
    def read_response(self):
        """Client端：从Server的stdout读取一条响应"""
        if self.out_buffer:
            return json.loads(self.out_buffer.popleft())
        return None


class SSETransport:
    """模拟SSE（Server-Sent Events）传输层
    
    实际中SSE传输：
      - Client通过HTTP连接到Server的SSE端点
      - Client通过HTTP POST发送请求
      - Server通过SSE事件流推送响应
      - 连接保持直到Client断开
    
    这里用两个队列模拟请求通道和响应通道。
    """
    
    def __init__(self):
        self.request_queue = deque()   # Client -> Server
        self.response_queue = deque()  # Server -> Client
        self.is_connected = False      # 连接状态
    
    def connect(self):
        """Client端：建立SSE连接"""
        self.is_connected = True
    
    def disconnect(self):
        """Client端：断开连接"""
        self.is_connected = False
    
    def send_request(self, message):
        """Client端：通过HTTP POST发送请求"""
        assert self.is_connected, "SSE not connected"
        self.request_queue.append(json.dumps(message))
    
    def receive_request(self):
        """Server端：接收Client的请求"""
        if self.request_queue:
            return json.loads(self.request_queue.popleft())
        return None
    
    def send_response(self, message):
        """Server端：通过SSE事件推送响应"""
        self.response_queue.append(json.dumps(message))
    
    def receive_response(self):
        """Client端：接收SSE事件"""
        if self.response_queue:
            return json.loads(self.response_queue.popleft())
        return None


def run_server_loop(server, transport, max_requests=10):
    """Server主循环：读取请求→处理→写回响应
    
    模拟真实的Server运行流程：
      1. 阻塞等待从Transport读取请求
      2. 调用handle_request处理请求
      3. 将响应写回Transport
      4. 循环直到没有更多请求
    """
    count = 0
    while count < max_requests:
        req = transport.receive()
        if req is None:
            break
        resp = server.handle_request(req)
        transport.send(resp)
        count += 1
    return count


# === 基础Server实现 ===
class MCPServer:
    def __init__(self, name="server", version="1.0.0"):
        self.name = name
        self.version = version
        self.tools = {}
    
    def register_tool(self, name, description, input_schema, handler):
        self.tools[name] = {"name": name, "description": description,
                            "inputSchema": input_schema, "handler": handler}
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        if method == "initialize":
            return {"jsonrpc": "2.0", "id": req_id, "result": {
                "protocolVersion": "2024-11-05",
                "serverInfo": {"name": self.name, "version": self.version},
                "capabilities": {"tools": {}}}}
        if method == "tools/list":
            tools = [{"name": t["name"], "description": t["description"],
                      "inputSchema": t["inputSchema"]} for t in self.tools.values()]
            return {"jsonrpc": "2.0", "id": req_id, "result": {"tools": tools}}
        if method == "tools/call":
            tool_name = params.get("name")
            arguments = params.get("arguments", {})
            if tool_name not in self.tools:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32601, "message": f"Unknown tool: {tool_name}"}}
            result = self.tools[tool_name]["handler"](arguments)
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"content": [{"type": "text", "text": str(result)}]}}
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}
```

## 模块2：Stateless MCP（无状态MCP）— 3题

### 知识点总览

**有状态 vs 无状态** 是分布式系统设计的核心决策：

```
┌─────────────────────────────────────────────────────────────┐
│                    状态管理对比                               │
│                                                              │
│  有状态 Server                     无状态 Server               │
│  ┌────────────┐                   ┌────────────┐             │
│  │  内存中有   │                   │  无内存状态 │             │
│  │  会话上下文 │                   │  每次请求   │             │
│  │            │                   │  自包含     │             │
│  └─────┬──────┘                   └──────┬─────┘             │
│        │                                  │                   │
│   请求依赖之前状态                   请求携带完整上下文          │
│   宕机丢失状态                      状态存在外部存储            │
│   无法水平扩展                      可自由水平扩展              │
└─────────────────────────────────────────────────────────────┘
```

**无状态 MCP 的设计原则**：
1. **每次请求自包含**：所有必要信息在请求参数中
2. **状态外部化**：将会话上下文存到 Redis/DB，而非内存
3. **幂等性**：同一请求重复执行结果一致

### 第487题：有状态MCP Server对比无状态版本

#### 知识点讲解

**有状态 MCP Server**：
- Server 在内存中维护每个会话的上下文（消息历史、变量等）
- 请求只需携带 `session_id`，Server 自动找到对应上下文
- 优点：请求体小，网络开销低
- 缺点：Server 重启后状态丢失；无法水平扩展（不同实例的内存不共享）

**无状态 MCP Server**：
- Server 不保存任何会话状态
- 每次请求需要携带完整的上下文（如消息历史）
- 优点：Server 可随时重启、水平扩展；天然支持负载均衡
- 缺点：请求体较大；上下文管理逻辑在 Client 侧

```python
import json

# ============================================================
# 第487题：有状态MCP Server对比无状态版本
# 实现两种Server处理多轮对话，对比状态管理方式
# ============================================================

class StatefulMCPServer:
    """有状态MCP Server
    
    Server内存维护会话上下文：
      - sessions: {session_id -> {messages: [...], counter: int}}
      
    优点：请求体小（只传session_id）
    缺点：重启丢失、不能水平扩展
    """
    
    def __init__(self, name="stateful-server", version="1.0.0"):
        self.name = name
        self.version = version
        self.sessions = {}  # 内存中的会话存储
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        session_id = params.get("_session_id", "default")
        
        # session/init —— 创建新会话
        if method == "session/init":
            self.sessions[session_id] = {"messages": [], "counter": 0}
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"session_id": session_id, "message": "Session created"}}
        
        # session/message —— 发送消息（依赖会话状态）
        if method == "session/message":
            if session_id not in self.sessions:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32602, "message": "Session not found. Init first."}}
            msg = params.get("message", "")
            # Server从内存中取出历史消息
            session = self.sessions[session_id]
            session["messages"].append(msg)
            session["counter"] += 1
            history = session["messages"]
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"reply": f"收到第{len(history)}条消息: {msg}",
                               "history": history}}
        
        # session/get_history —— 获取会话历史
        if method == "session/get_history":
            if session_id not in self.sessions:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32602, "message": "Session not found"}}
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"history": self.sessions[session_id]["messages"]}}
        
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}


class StatelessMCPServer:
    """无状态MCP Server
    
    Server不保存任何会话状态：
      - 每次请求携带完整的消息历史
      - Server只负责处理当前请求，返回更新后的历史
      
    优点：可水平扩展、重启无影响、天然支持负载均衡
    缺点：请求体大（需携带完整历史）
    """
    
    def __init__(self, name="stateless-server", version="1.0.0"):
        self.name = name
        self.version = version
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        
        # session/message —— Client自带历史，Server无状态处理
        if method == "session/message":
            msg = params.get("message", "")
            # 历史由Client提供，Server不存储
            history = params.get("history", [])
            new_history = history + [msg]
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"reply": f"收到第{len(new_history)}条消息: {msg}",
                               "history": new_history}}
        
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}
```

### 第488题：无状态MCP + 外部状态存储（JSON文件模拟Redis）

#### 知识点讲解

**状态外部化**是无状态架构的关键模式：Server 本身无状态，但将状态存到外部存储（Redis/DB/文件系统）。

```
┌─────────┐     请求（携带session_id）      ┌─────────────┐
│ Client  │ ──────────────────────────────> │ Stateless   │
│         │                                 │ MCP Server  │
│         │ <────── 响应 ───────────────── │             │
└─────────┘                                 └──────┬──────┘
                                                   │ 存取状态
                                                   ▼
                                            ┌──────────────┐
                                            │ Redis / DB   │
                                            │ (外部存储)    │
                                            └──────────────┘
```

**工作流程**：
1. Client 发送请求，携带 `session_id`
2. Server 从外部存储加载该 session 的上下文
3. Server 处理请求，更新上下文
4. Server 将更新后的上下文写回外部存储
5. Server 返回响应

这样 Server 可以任意重启、水平扩展——状态始终安全存储在外部。

```python
import json
import os

# ============================================================
# 第488题：无状态MCP + 外部状态存储
# 用JSON文件模拟Redis，实现状态持久化
# ============================================================

class ExternalStateStore:
    """外部状态存储（模拟Redis）
    
    用JSON文件模拟Redis的key-value存储：
      - get(key): 获取值
      - set(key, value): 设置值
      - delete(key): 删除值
      - keys(): 列出所有key
    
    实际生产中替换为Redis客户端即可：
      redis.get(key) / redis.set(key, value) / redis.delete(key)
    """
    
    def __init__(self, filepath):
        """初始化存储，从文件加载已有数据
        
        参数:
            filepath: JSON文件路径，用于持久化存储
        """
        self.filepath = filepath
        self._data = {}
        # 从文件恢复已有数据（模拟Redis重启后从RDB恢复）
        if os.path.exists(filepath):
            with open(filepath, 'r') as f:
                self._data = json.load(f)
    
    def get(self, key):
        """获取指定key的值"""
        return self._data.get(key)
    
    def set(self, key, value):
        """设置key-value，并持久化到文件"""
        self._data[key] = value
        self._persist()
    
    def delete(self, key):
        """删除指定key"""
        if key in self._data:
            del self._data[key]
            self._persist()
    
    def keys(self):
        """列出所有key"""
        return list(self._data.keys())
    
    def _persist(self):
        """将数据写入文件（模拟Redis的RDB快照）"""
        with open(self.filepath, 'w') as f:
            json.dump(self._data, f, ensure_ascii=False)


class StatelessMCPWithStore:
    """无状态MCP Server + 外部状态存储
    
    Server本身无状态：
      - 不在内存中保存会话
      - 每次请求时从外部存储加载会话上下文
      - 处理完成后将更新写回外部存储
    
    优势：
      - Server可随时重启（状态在外部存储中）
      - 可水平扩展（多个Server共享同一存储）
      - 可通过外部存储实现会话过期清理
    """
    
    def __init__(self, store, name="stateless-store-server", version="1.0.0"):
        self.name = name
        self.version = version
        self.store = store  # 外部状态存储
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        
        # session/save —— 保存会话上下文到外部存储
        if method == "session/save":
            session_id = params.get("session_id")
            context = params.get("context")
            self.store.set(session_id, context)
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"saved": True, "session_id": session_id}}
        
        # session/load —— 从外部存储加载会话上下文
        if method == "session/load":
            session_id = params.get("session_id")
            context = self.store.get(session_id)
            if context is None:
                return {"jsonrpc": "2.0", "id": req_id,
                        "error": {"code": -32602, "message": "Session not found"}}
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"session_id": session_id, "context": context}}
        
        # session/delete —— 删除会话
        if method == "session/delete":
            session_id = params.get("session_id")
            self.store.delete(session_id)
            return {"jsonrpc": "2.0", "id": req_id, "result": {"deleted": True}}
        
        # session/append_message —— 追加消息到会话（原子操作模拟）
        if method == "session/append_message":
            session_id = params.get("session_id")
            message = params.get("message", "")
            # 1. 加载现有上下文
            context = self.store.get(session_id) or {"messages": []}
            # 2. 追加新消息
            context["messages"].append(message)
            context["message_count"] = len(context["messages"])
            # 3. 写回外部存储
            self.store.set(session_id, context)
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"reply": f"收到第{context['message_count']}条消息: {message}",
                               "context": context}}
        
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}
```

### 第489题：无状态MCP负载均衡模拟（轮询多个Server实例）

#### 知识点讲解

**负载均衡**是无状态架构的核心优势。由于每个 Server 实例都是无状态的，请求可以分发到任意实例：

```
                   ┌──────────────┐
        请求 ──────>│  LoadBalancer │
                   │  (轮询分发)    │
                   └──┬──┬──┬──────┘
                      │  │  │
              ┌───────┘  │  └───────┐
              ▼          ▼          ▼
         ┌────────┐ ┌────────┐ ┌────────┐
         │Server A│ │Server B│ │Server C│
         │(无状态) │ │(无状态) │ │(无状态) │
         └────────┘ └────────┘ └────────┘
              │          │          │
              └──────────┴──────────┘
                         │
                  共享外部状态存储
                  (Redis / Database)
```

**轮询算法（Round Robin）**：
- 维护一个计数器 `index`，每次请求递增
- `server = servers[index % len(servers)]`
- 保证请求均匀分布到所有实例

**负载均衡的验证指标**：
- 每个实例处理的请求数应大致相等
- 请求顺序应严格轮询（A→B→C→A→B→C→...）

```python
import json

# ============================================================
# 第489题：无状态MCP负载均衡模拟
# 实现轮询负载均衡器，分发请求到多个无状态Server实例
# ============================================================

class StatelessMCPServer:
    """无状态MCP Server（复用第487题）"""
    
    def __init__(self, name="stateless-server", version="1.0.0"):
        self.name = name
        self.version = version
        self.request_count = 0  # 统计每个实例处理的请求数
    
    def handle_request(self, request):
        req_id = request.get("id")
        method = request.get("method", "")
        params = request.get("params", {})
        self.request_count += 1  # 计数
        
        if method == "session/message":
            msg = params.get("message", "")
            history = params.get("history", [])
            new_history = history + [msg]
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"reply": f"[{self.name}] 收到: {msg}",
                               "history": new_history,
                               "server": self.name}}
        
        if method == "ping":
            return {"jsonrpc": "2.0", "id": req_id,
                    "result": {"pong": True, "server": self.name}}
        
        return {"jsonrpc": "2.0", "id": req_id,
                "error": {"code": -32601, "message": f"Method not found: {method}"}}


class LoadBalancer:
    """轮询负载均衡器
    
    策略：
      - 每次请求选择 index % len(servers) 的Server实例
      - index 递增，实现均匀分布
    
    特性：
      - 无状态Server可随时增减实例
      - 请求日志可追踪每个请求被分发到哪个实例
    """
    
    def __init__(self, servers):
        """初始化负载均衡器
        
        参数:
            servers: Server实例列表
        """
        self.servers = servers
        self.index = 0          # 轮询计数器
        self.request_log = []   # 请求分发日志
    
    def route(self, request):
        """将请求路由到下一个Server（轮询）"""
        if not self.servers:
            raise RuntimeError("No servers available")
        # 轮询选择
        server = self.servers[self.index % len(self.servers)]
        self.index += 1
        self.request_log.append(server.name)
        return server.handle_request(request)
    
    def get_distribution(self):
        """返回每个Server处理的请求数统计"""
        counts = {}
        for name in self.request_log:
            counts[name] = counts.get(name, 0) + 1
        return counts
    
    def add_server(self, server):
        """动态添加Server实例"""
        self.servers.append(server)
    
    def remove_server(self, name):
        """动态移除Server实例"""
        self.servers = [s for s in self.servers if s.name != name]
```

## 模块3：Graph Engineering（图结构工程）— 5题

### 知识点总览

**图结构工程**是 Agent 工作流编排的核心技术，以 LangGraph 的 StateGraph 为代表。核心概念：

```
┌─────────────────────────────────────────────────────────────┐
│                   StateGraph 核心概念                        │
│                                                              │
│   ┌─────┐     ┌─────┐                                       │
│   │Node │────>│Node │   节点（Node）：执行单元               │
│   │  A  │     │  B  │   边（Edge）：控制流                   │
│   └─────┘     └──┬──┘                                       │
│                  │                                           │
│           ┌──────┴──────┐                                   │
│           ▼             ▼     条件分支：根据状态选择路径       │
│        ┌─────┐      ┌─────┐                                  │
│        │Node │      │Node │   并行：多个节点同时执行           │
│        │  C  │      │  D  │   汇合：等待并行结果后继续         │
│        └─────┘      └─────┘                                  │
│           │             │                                    │
│           └──────┬──────┘   检查点：保存中间状态              │
│                  ▼          人机协作：暂停等待人工输入          │
│              ┌─────┐                                       │
│              │Node │                                       │
│              │  E  │                                       │
│              └─────┘                                       │
└─────────────────────────────────────────────────────────────┘
```

| 概念 | 说明 | 类比 |
|------|------|------|
| State | 在节点间传递的数据字典 | 函数的参数+返回值 |
| Node | 接收State、处理、返回更新后的State | 函数 |
| Edge | 连接两个Node，定义执行顺序 | 函数调用链 |
| Conditional Edge | 根据State动态选择下一个Node | if/else |
| Checkpoint | 保存某节点的State快照 | 存档点 |
| Human-in-the-loop | 暂停执行等待人工输入 | 游戏暂停 |

### 第490题：线性状态图 —— 3个节点串联执行

#### 知识点讲解

**线性状态图**是最简单的图结构：节点按顺序串联执行，每个节点接收上一个节点的输出状态。

```
[入口] → Node_A → Node_B → Node_C → [结束]
```

**State 的传递方式**：
- 初始 State 在 `run()` 时传入
- 每个节点接收 State，处理后返回**更新后的** State
- State 是一个 dict，节点可以读取已有字段、添加新字段、修改已有字段

**与函数管道的区别**：
- 函数管道：`f3(f2(f1(x)))`，只能传递返回值
- 状态图：每个节点可以读取 State 中的所有字段，而不仅仅是前一个节点的输出

```python
# ============================================================
# 第490题：线性状态图
# 实现3个节点串联执行的状态图引擎
# ============================================================

class StateGraph:
    """状态图引擎
    
    核心组件：
      - nodes: 节点注册表 {name -> function(state) -> state}
      - edges: 边定义 {src -> [dst]} 或条件边
      - entry: 入口节点名
    
    节点函数签名：
      def node_fn(state: dict) -> dict
    节点接收当前State，返回更新后的State。
    """
    
    def __init__(self):
        self.nodes = {}      # 节点名 -> 处理函数
        self.edges = {}       # 节点名 -> 下一节点列表（或条件边定义）
        self.entry = None     # 入口节点
        self.checkpoints = {}  # 检查点存储（第12题使用）
    
    def add_node(self, name, fn):
        """注册一个节点
        
        参数:
            name: 节点名（唯一标识）
            fn: 节点处理函数，签名 fn(state: dict) -> dict
        """
        self.nodes[name] = fn
    
    def add_edge(self, src, dst):
        """添加一条边：从src节点执行后跳转到dst节点
        
        参数:
            src: 源节点名
            dst: 目标节点名
        """
        if src not in self.edges:
            self.edges[src] = []
        self.edges[src].append(dst)
    
    def set_entry(self, name):
        """设置入口节点"""
        self.entry = name
    
    def add_conditional_edge(self, src, condition_fn, mapping):
        """添加条件边
        
        参数:
            src: 源节点名
            condition_fn: 条件函数 fn(state) -> key
            mapping: {key -> 目标节点名}
            
        执行时：condition_fn(state)返回key，根据mapping选择下一个节点
        """
        self.edges[src] = {"_conditional": True, "fn": condition_fn, "mapping": mapping}
    
    def run(self, initial_state):
        """执行状态图
        
        参数:
            initial_state: 初始状态字典
        
        返回:
            {
                "state": 最终状态,
                "path": 经过的节点路径列表
            }
        """
        assert self.entry is not None, "No entry node set"
        state = initial_state.copy()
        current = self.entry
        path = []  # 记录执行路径
        
        while current is not None:
            path.append(current)
            # 执行当前节点
            state = self.nodes[current](state)
            
            # 查找下一个节点
            next_nodes = self.edges.get(current)
            if next_nodes is None:
                # 没有出边，结束执行
                break
            elif isinstance(next_nodes, dict) and next_nodes.get("_conditional"):
                # 条件边：根据状态选择路径
                key = next_nodes["fn"](state)
                current = next_nodes["mapping"].get(key)
            elif isinstance(next_nodes, list):
                # 普通边：取第一个目标
                current = next_nodes[0] if next_nodes else None
            else:
                current = None
        
        return {"state": state, "path": path}


# === 运行测试 ===
graph = StateGraph()
```

### 第491题：条件分支状态图 —— 根据状态值选择不同路径

#### 知识点讲解

**条件分支**是状态图实现智能路由的核心机制。与线性图不同，条件边根据当前 State 的值动态决定下一个执行节点：

```
                 ┌──> [grade_a] ──┐
[classify] ──────┤──> [grade_b] ──┼──> [finish]
                 └──> [grade_c] ──┘
```

**条件边的三要素**：
1. `condition_fn(state) -> key`：从 State 中提取路由键
2. `mapping: {key -> node_name}`：路由映射表
3. 如果 key 不在 mapping 中，返回 None，结束执行

**与 if/else 的区别**：
- if/else 是代码内嵌的，修改路由逻辑需要改代码
- 条件边是数据驱动的，修改 mapping 即可调整路由

```python
# ============================================================
# 第491题：条件分支状态图
# 根据状态值选择不同执行路径
# ============================================================

class StateGraph:
    def __init__(self):
        self.nodes = {}
        self.edges = {}
        self.entry = None
    
    def add_node(self, name, fn):
        self.nodes[name] = fn
    
    def add_edge(self, src, dst):
        if src not in self.edges:
            self.edges[src] = []
        self.edges[src].append(dst)
    
    def set_entry(self, name):
        self.entry = name
    
    def add_conditional_edge(self, src, condition_fn, mapping):
        """条件边：condition_fn(state)返回key，mapping[key]给出目标节点"""
        self.edges[src] = {"_conditional": True, "fn": condition_fn, "mapping": mapping}
    
    def run(self, initial_state):
        assert self.entry is not None
        state = initial_state.copy()
        current = self.entry
        path = []
        while current is not None:
            path.append(current)
            state = self.nodes[current](state)
            next_nodes = self.edges.get(current)
            if next_nodes is None:
                break
            elif isinstance(next_nodes, dict) and next_nodes.get("_conditional"):
                key = next_nodes["fn"](state)
                current = next_nodes["mapping"].get(key)
            elif isinstance(next_nodes, list):
                current = next_nodes[0] if next_nodes else None
            else:
                current = None
        return {"state": state, "path": path}
```

### 第492题：并行节点+汇合 —— fork-join模式

#### 知识点讲解

**Fork-Join 模式**允许状态图在某个节点之后并行执行多个分支，然后在汇合点等待所有分支完成后继续：

```
              ┌──> [extract_keywords] ──┐
[start] ──────┤                          ├──> [merge] ──> [end]
              └──> [count_words] ────────┘
```

**Fork 阶段**：
- 将当前 State 的副本分发给多个并行节点
- 每个节点独立处理，返回各自的结果

**Join 阶段**：
- 收集所有并行节点的结果
- 通过 merge 函数将多个结果合并为一个 State
- 合并策略：字段覆盖、列表拼接、自定义逻辑

**并行模拟**：
由于 Python 的 GIL，真正的并行需要多进程。这里用顺序执行模拟并行——逻辑上每个分支独立处理 State 副本，互不干扰。

```python
# ============================================================
# 第492题：并行节点+汇合（fork-join模式）
# 实现并行分支执行和结果汇合
# ============================================================

class ParallelStateGraph:
    """支持并行fork-join的状态图
    
    新增概念：
      - fork: 一个节点之后分裂为多个并行分支
      - join: 等待所有分支完成后合并结果
    
    State在fork时被复制给每个分支（深拷贝语义）
    State在join时通过merge_fn合并
    """
    
    def __init__(self):
        self.nodes = {}
        self.edges = {}
        self.entry = None
        self.fork_targets = {}   # fork节点 -> [并行分支节点名]
        self.join_points = {}    # join节点 -> {sources, merge_fn}
    
    def add_node(self, name, fn):
        self.nodes[name] = fn
    
    def set_entry(self, name):
        self.entry = name
    
    def add_edge(self, src, dst):
        if src not in self.edges:
            self.edges[src] = []
        self.edges[src].append(dst)
    
    def add_fork(self, src, targets):
        """定义fork：src节点执行后，并行执行targets中的所有节点"""
        self.fork_targets[src] = targets
        self.edges[src] = targets
    
    def add_join(self, join_node, sources, merge_fn=None):
        """定义join：在join_node处合并所有并行分支的结果
        
        参数:
            join_node: 汇合节点名
            sources: fork起始节点名（用于定位并行结果）
            merge_fn: 合并函数 fn(list_of_states) -> merged_state
                     默认：将所有State的字段合并（后者覆盖前者）
        """
        if merge_fn is None:
            merge_fn = lambda results: {k: v for r in results for k, v in r.items()}
        self.join_points[join_node] = {"sources": sources, "merge_fn": merge_fn}
    
    def run(self, initial_state):
        """执行状态图，支持并行fork-join"""
        assert self.entry is not None
        state = initial_state.copy()
        current = self.entry
        path = []
        
        while current is not None:
            path.append(current)
            
            # 检查是否为join点
            if current in self.join_points:
                join_info = self.join_points[current]
                # 合并并行结果
                parallel_results = state.pop("_parallel_results", [state])
                state = join_info["merge_fn"](parallel_results)
                # 执行join节点
                state = self.nodes[current](state)
                # 继续到下一个节点
                next_nodes = self.edges.get(current)
                current = next_nodes[0] if next_nodes else None
                continue
            
            # 执行当前节点
            state = self.nodes[current](state)
            
            # 检查是否为fork点
            if current in self.fork_targets:
                targets = self.fork_targets[current]
                # 模拟并行：每个分支独立处理State副本
                parallel_states = []
                for t in targets:
                    path.append(t)  # 记录并行分支到执行路径
                    ps = state.copy()  # 每个分支获得State副本
                    ps = self.nodes[t](ps)
                    parallel_states.append(ps)
                # 存储并行结果，等待join
                state["_parallel_results"] = parallel_states
                
                # 查找对应的join节点
                join_found = False
                for node_name in self.nodes:
                    if node_name in self.join_points:
                        join_info = self.join_points[node_name]
                        if current in join_info["sources"]:
                            current = node_name
                            join_found = True
                            break
                if not join_found:
                    break
            else:
                # 普通节点：继续到下一个
                next_nodes = self.edges.get(current)
                if isinstance(next_nodes, list) and len(next_nodes) > 0:
                    current = next_nodes[0]
                else:
                    current = None
        
        return {"state": state, "path": path}
```

### 第493题：带检查点的状态图 —— 保存中间状态、可恢复

#### 知识点讲解

**检查点（Checkpoint）**是状态图的"存档"功能：在指定节点保存当前 State 的快照，以便后续从该点恢复执行。

```
[fetch] → [transform]* → [analyze] → [report]
                    ↑
              Checkpoint保存点
              
恢复执行：
  从Checkpoint加载 → 跳过已执行节点 → 继续后续节点
```

**检查点的应用场景**：
1. **长流程恢复**：耗时任务中途失败，从检查点恢复而非从头开始
2. **调试回放**：从检查点重放，排查问题
3. **人机协作**：在人工审批前保存检查点，审批后恢复

**检查点的数据结构**：
```python
{
    "node": "transform",      # 保存时的节点名
    "state": {"step": 2},     # 保存时的State快照
    "path": ["fetch", "transform"]  # 已执行路径
}
```

```python
# ============================================================
# 第493题：带检查点的状态图
# 实现检查点保存和恢复功能
# ============================================================

class CheckpointStateGraph:
    """带检查点功能的状态图
    
    功能：
      1. 在指定节点自动保存检查点
      2. 从检查点恢复执行（跳过已执行节点）
      3. 查看检查点内容
    
    检查点存储：
      checkpoint_store: {checkpoint_id -> {node, state, path}}
    """
    
    def __init__(self):
        self.nodes = {}
        self.edges = {}
        self.entry = None
        self.checkpoint_store = {}  # 检查点存储
    
    def add_node(self, name, fn):
        self.nodes[name] = fn
    
    def add_edge(self, src, dst):
        if src not in self.edges:
            self.edges[src] = []
        self.edges[src].append(dst)
    
    def set_entry(self, name):
        self.entry = name
    
    def add_conditional_edge(self, src, condition_fn, mapping):
        self.edges[src] = {"_conditional": True, "fn": condition_fn, "mapping": mapping}
    
    def save_checkpoint(self, node_name, state, path):
        """保存检查点
        
        在节点执行前保存当前State的快照
        返回检查点ID
        """
        cp_id = f"cp_{len(self.checkpoint_store)}"
        self.checkpoint_store[cp_id] = {
            "node": node_name,
            "state": state.copy(),    # 深拷贝State
            "path": path.copy()       # 深拷贝路径
        }
        return cp_id
    
    def load_checkpoint(self, cp_id):
        """加载检查点
        
        返回: (node_name, state_copy, path_copy)
        异常: 检查点不存在时抛出KeyError
        """
        if cp_id not in self.checkpoint_store:
            raise KeyError(f"Checkpoint not found: {cp_id}")
        cp = self.checkpoint_store[cp_id]
        return cp["node"], cp["state"].copy(), cp["path"].copy()
    
    def list_checkpoints(self):
        """列出所有检查点"""
        return {cp_id: {"node": cp["node"], "path": cp["path"]}
                for cp_id, cp in self.checkpoint_store.items()}
    
    def run_with_checkpoints(self, initial_state, checkpoint_nodes=None):
        """执行图并在指定节点保存检查点
        
        参数:
            initial_state: 初始状态
            checkpoint_nodes: 需要保存检查点的节点名集合
                            在这些节点执行前保存State快照
        返回:
            {state, path, checkpoints}
        """
        assert self.entry is not None
        checkpoint_nodes = checkpoint_nodes or set()
        state = initial_state.copy()
        current = self.entry
        path = []
        checkpoints = []
        
        while current is not None:
            path.append(current)
            
            # 在指定节点执行前保存检查点
            if current in checkpoint_nodes:
                cp_id = self.save_checkpoint(current, state, path)
                checkpoints.append(cp_id)
            
            # 执行节点
            state = self.nodes[current](state)
            
            # 查找下一个节点
            next_nodes = self.edges.get(current)
            if next_nodes is None:
                break
            elif isinstance(next_nodes, dict) and next_nodes.get("_conditional"):
                key = next_nodes["fn"](state)
                current = next_nodes["mapping"].get(key)
            elif isinstance(next_nodes, list):
                current = next_nodes[0] if next_nodes else None
            else:
                current = None
        
        return {"state": state, "path": path, "checkpoints": checkpoints}
    
    def resume_from_checkpoint(self, cp_id, checkpoint_nodes=None):
        """从检查点恢复执行
        
        1. 加载检查点中的State和路径
        2. 从检查点节点重新开始执行（检查点保存的是执行前的状态）
        3. 继续执行后续节点
        
        参数:
            cp_id: 检查点ID
            checkpoint_nodes: 恢复执行时的检查点节点
        """
        checkpoint_nodes = checkpoint_nodes or set()
        node, state, path = self.load_checkpoint(cp_id)
        
        # 从检查点节点重新执行（检查点保存的是该节点执行前的状态）
        # 移除path末尾的检查点节点名，避免重复记录
        if path and path[-1] == node:
            path.pop()
        current = node
        
        # 从检查点节点继续执行
        while current is not None:
            path.append(current)
            if current in checkpoint_nodes:
                self.save_checkpoint(current, state, path)
            state = self.nodes[current](state)
            next_nodes = self.edges.get(current)
            if next_nodes is None:
                break
            elif isinstance(next_nodes, dict) and next_nodes.get("_conditional"):
                key = next_nodes["fn"](state)
                current = next_nodes["mapping"].get(key)
            elif isinstance(next_nodes, list):
                current = next_nodes[0] if next_nodes else None
            else:
                current = None
        
        return {"state": state, "path": path}
```

### 第494题：Human-in-the-loop节点 —— 暂停等待人工输入后继续

#### 知识点讲解

**Human-in-the-loop（HITL）** 是 Agent 工作流中的关键模式：在图的某个节点暂停执行，等待人工输入后继续。

```
[draft] → [review] → [approve]* → [process_decision] → [publish]
                          ↑
                    暂停等待人工输入
                    "批准" or "拒绝"
```

**HITL 的典型场景**：
1. **审批流程**：AI 生成方案后，人工审批是否发布
2. **信息确认**：AI 提取关键信息后，人工确认准确性
3. **风险控制**：高风险操作前，人工二次确认
4. **反馈收集**：AI 提出建议，人工提供反馈指导后续步骤

**实现机制**：
1. 图执行到人工节点时，返回 `status="awaiting_human"` 和提示信息
2. 调用方收集人工输入，通过 `provide_human_input()` 注入
3. 重新执行图，人工节点检测到已有输入，继续执行

**状态管理**：
- 人工输入存储在 `human_inputs[run_id][node_name]` 中
- 支持多个独立的运行实例（不同 `run_id`）

```python
# ============================================================
# 第494题：Human-in-the-loop节点
# 实现暂停等待人工输入后继续执行的状态图
# ============================================================

class HITLStateGraph:
    """支持人机协作节点的状态图
    
    核心机制：
      1. 人工节点执行时设置 _awaiting_human 标志
      2. 检查是否已有人工输入：
         - 有：清除标志，继续执行
         - 无：返回暂停状态，等待输入
      3. 调用方提供输入后，重新执行图
    
    多运行实例支持：
      不同 run_id 的执行互不干扰
      human_inputs[run_id][node_name] 存储每个实例的输入
    """
    
    def __init__(self):
        self.nodes = {}
        self.edges = {}
        self.entry = None
        self.human_inputs = {}   # {run_id -> {node_name -> input_value}}
        self._human_nodes = set()  # 人工节点名集合
    
    def add_node(self, name, fn):
        """注册普通节点"""
        self.nodes[name] = fn
    
    def add_human_node(self, name, prompt_fn=None):
        """注册人工节点
        
        参数:
            name: 节点名
            prompt_fn: 提示函数 fn(state) -> str
                      生成给人工的提示信息
        
        人工节点的行为：
          1. 执行时设置 _awaiting_human = True
          2. 检查 human_inputs 中是否已有输入
          3. 有输入：注入 _human_decision，继续执行
          4. 无输入：返回暂停状态
        """
        def human_fn(state):
            state["_awaiting_human"] = True
            state["_human_prompt"] = prompt_fn(state) if prompt_fn else "请输入您的决定："
            return state
        
        self.nodes[name] = human_fn
        self._human_nodes.add(name)
    
    def add_edge(self, src, dst):
        if src not in self.edges:
            self.edges[src] = []
        self.edges[src].append(dst)
    
    def set_entry(self, name):
        self.entry = name
    
    def provide_human_input(self, run_id, node_name, input_value):
        """提供人工输入
        
        参数:
            run_id: 运行实例ID
            node_name: 人工节点名
            input_value: 人工输入值（如 "approve" / "reject"）
        """
        if run_id not in self.human_inputs:
            self.human_inputs[run_id] = {}
        self.human_inputs[run_id][node_name] = input_value
    
    def run_with_human(self, initial_state, run_id="default"):
        """执行图，遇到人工节点暂停等待
        
        返回值:
          - status="awaiting_human": 暂停，需要人工输入
            包含 human_prompt 和 pending_node
          - status="completed": 执行完成
            包含最终 state 和 path
        """
        state = initial_state.copy()
        current = self.entry
        path = []
        
        while current is not None:
            path.append(current)
            
            # 执行当前节点
            node_fn = self.nodes[current]
            state = node_fn(state)
            
            # 检查是否是人工节点且等待输入
            if state.get("_awaiting_human"):
                # 检查是否已有人工输入
                human_input = self.human_inputs.get(run_id, {}).get(current)
                if human_input is not None:
                    # 已有输入：注入决策，继续执行
                    state["_human_decision"] = human_input
                    state["_awaiting_human"] = False
                    state.pop("_human_prompt", None)
                    # 继续到下一个节点
                    next_nodes = self.edges.get(current, [])
                    current = next_nodes[0] if next_nodes else None
                else:
                    # 暂停：等待人工输入
                    return {
                        "state": state,
                        "path": path,
                        "status": "awaiting_human",
                        "human_prompt": state.get("_human_prompt"),
                        "pending_node": current
                    }
            else:
                # 普通节点：继续执行
                next_nodes = self.edges.get(current, [])
                current = next_nodes[0] if next_nodes else None
        
        return {"state": state, "path": path, "status": "completed"}

print("--- 场景1：第一轮运行（暂停等待审批）---")
result1 = graph.run_with_human({"project": "项目A"}, run_id="run-001")
assert result1["status"] == "awaiting_human"
print(f"  状态: {result1['status']}")
print(f"  暂停节点: {result1['pending_node']}")
print(f"  人工提示:\n{result1['human_prompt']}")
print(f"  已执行路径: {result1['path']}")
assert result1["path"] == ["draft", "review", "approve"]
assert "草稿内容" in result1["state"]["content"]

# === 场景2：人工批准后继续执行 ===
print("\n--- 场景2：人工批准后继续 ---")
graph.provide_human_input("run-001", "approve", "approve")
result2 = graph.run_with_human({"project": "项目A"}, run_id="run-001")
assert result2["status"] == "completed"
assert result2["state"]["status"] == "approved"
assert result2["state"]["published"] == True
print(f"  状态: {result2['status']}")
print(f"  审批结果: {result2['state']['status']}")
print(f"  已发布: {result2['state']['published']}")
print(f"  执行路径: {result2['path']}")
for entry in result2["state"]["log"]:
    print(f"    {entry}")

# === 场景3：另一个运行实例，人工拒绝 ===
print("\n--- 场景3：另一个实例，人工拒绝 ---")
graph.provide_human_input("run-002", "approve", "reject")
result3 = graph.run_with_human({"project": "项目B"}, run_id="run-002")
assert result3["state"]["status"] == "rejected"
assert result3["state"]["published"] == False
print(f"  状态: {result3['state']['status']}")
print(f"  已发布: {result3['state']['published']}")
for entry in result3["state"]["log"]:
    print(f"    {entry}")

# === 场景4：多个人工节点的场景 ===
print("\n--- 场景4：多个人工节点 ---")
graph2 = HITLStateGraph()
graph2.add_node("start", lambda s: {**s, "step": 1, "log": ["start"]})
graph2.add_human_node("review1", lambda s: "第一次审查：approve 或 reject？")
graph2.add_node("process1", lambda s: {**s, "step": 2, "r1": s.get("_human_decision",""), "log": s["log"]+["process1"]})
graph2.add_human_node("review2", lambda s: "第二次审查：approve 或 reject？")
graph2.add_node("end", lambda s: {**s, "step": 3, "r2": s.get("_human_decision",""), "log": s["log"]+["end"], "done": True})
graph2.set_entry("start")
graph2.add_edge("start", "review1")
graph2.add_edge("review1", "process1")
graph2.add_edge("process1", "review2")
graph2.add_edge("review2", "end")

# 第一轮：在review1暂停
r = graph2.run_with_human({"init": True}, run_id="multi-001")
assert r["status"] == "awaiting_human"
assert r["pending_node"] == "review1"
print(f"  第一轮: 暂停在 {r['pending_node']}")

# 提供第一次审查输入
graph2.provide_human_input("multi-001", "review1", "approve")
r = graph2.run_with_human({"init": True}, run_id="multi-001")
assert r["status"] == "awaiting_human"
assert r["pending_node"] == "review2"
print(f"  第二轮: 通过review1, 暂停在 {r['pending_node']}")

# 提供第二次审查输入
graph2.provide_human_input("multi-001", "review2", "approve")
r = graph2.run_with_human({"init": True}, run_id="multi-001")
assert r["status"] == "completed"
assert r["state"]["r1"] == "approve"
assert r["state"]["r2"] == "approve"
assert r["state"]["done"] == True
print(f"  第三轮: 全部通过, r1={r['state']['r1']}, r2={r['state']['r2']}")
```
